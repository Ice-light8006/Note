## 第一阶段：确认需求和缩小范围

最终版本建议确定为：


```
STM32 + 指纹 + OLED/TFT + RTC + Wi-Fi + 语音
```

暂不加入：


```
RFID人脸识别摄像头行为检测原生 Android APP复杂云平台
```

原因是这些内容会显著增加工作量，而且不是任务书的必选核心。

## 第二阶段：单独调试每个模块

调试顺序建议如下：

1. STM32 时钟、GPIO、串口；
2. OLED 或 TFT 显示；
3. 按键；
4. DS3231 或 STM32 RTC；
5. 指纹模块；
6. 语音模块；
7. ESP8266；
8. 本地 Flash 存储；
9. 所有模块联合调试。

每个模块都要形成独立测试结果，例如：

```
串口测试：能够收发指定字符串显示测试：能够显示固定文字指纹测试：录入、搜索、删除均成功Wi-Fi 测试：能够连接路由器并上传数据RTC 测试：断电后时间仍然保持
```

## 第三阶段：先完成本地考勤

先不要接服务器，完成：

```
指纹录入指纹删除指纹验证签到签退学习时长计算本地显示语音播报
```

这个阶段完成后，已经具备一个完整的离线考勤系统。

## 第四阶段：加入 Wi-Fi

再实现：


```
ESP8266 初始化连接路由器上传签到数据上传签退数据服务器应答处理断网重连离线缓存
```

## 第五阶段：开发网页端

网页端至少包含：

- 今日记录；
- 历史记录；
- 学生学习时长统计；
- 在线/离线状态；
- 异常记录。

## 第六阶段：系统测试

建议设计以下测试表：

|测试项目|测试方法|评价指标|
|---|---|---|
|指纹录入|连续录入多枚指纹|录入成功率|
|指纹识别|同一指纹重复识别|识别成功率|
|错误指纹|使用未录入指纹|拒绝成功|
|签到逻辑|同一学生首次打卡|正确生成签到|
|签退逻辑|再次打卡|正确生成签退和时长|
|重复打卡|5 秒内连续打卡|不重复生成记录|
|Wi-Fi 上传|正常网络下测试|数据完整到达|
|断网缓存|断开路由器测试|本地不丢数据|
|恢复补传|恢复网络测试|自动补传|
|掉电恢复|签到后重启设备|状态正确恢复|
|长时间运行|连续运行 8 至 24 小时|无死机、无内存泄漏|****
