# FIEL对象
假如我打开
```c
test.txt
```
程序在读取文件时，光知道文件名肯定不够，C标准库还要记录很多东西，例如
```
test.txt

当前读到哪里了？
是否到 EOF？
是否发生错误？
是读模式还是写模式？
缓冲区里面有什么？
底层对应哪个文件？
```
所以标准库维护一个对象，大致可以想象成
```c
struct FILE
{
    文件当前位置;
    文件模式;
    缓冲区;
    EOF状态;
    错误状态;
    底层文件信息;
    ...
};
```
这个对象就是`FILE`对象
当然，这只是帮助理解的伪代码，真实实际情况不一定长这样
而`FILE*`就是一个指向`FILE`对象的指针
# `stdin`,`stdout`,`stderr`
`stdin`、`stdout`、`stderr` 其实也是 `FILE *`
C程序启动时一般已经有三个标准流
```c
stdin
stdout
stderr
```
它们本质上都是
```c
FILE *
```
可以理解成
```
stdin:指向标准输入流FILE对象的指针
stdout:指向标注输出流FILE对象的指针
stderr:指向标准错误流FILE对象的指针
```
所以
```c
fprintf(stdout,"hello\n");
```
和
```c
printf("hello\n");
```
在功能上其实很接近
又比如
```c
fgetc(stdin);
```
其实就是：
```
从标准输入流获得一个字符
```
# `fopen`
## 语法
```c
FILE* fopen(const char* path, const char *mode);
```
这里`path`是文件的路径
而`mode`是打开模式
## 文件读写模式

| 模式          | 含义                                                            |
| ----------- | ------------------------------------------------------------- |
| `r`         | 打开只读文件，文件必须存在                                                 |
| `r+`        | 打开可读写的文件，文件必须存在                                               |
| `w`         | 打开只写文件，若文件存在会清空，若文件不存在则创建该文件                                  |
| `w+`        | 打开可读写的文件，若文件存在则文件清空，若文件不存在则创建文件                               |
| `a`         | 以追加的方式打开只写文件，若文件不存在则会创建文件，啊如果文件存在，写入的数据会被追加到文件末尾，即文件原先的内容会被保留 |
| `a+`        | 以追加的方式打开可读可写文件，若文件不存在，则会创建该文件                                 |
| `r+b`/`rb+` | 二进制读写                                                         |
| `w+b`/`wb+` | 二进制读写（清空/创建）                                                  |
>**重要提示**：在 Windows 系统下，文本模式（`r`、`w`）会对 `\r\n` 做自动转换，而二进制模式（`rb`、`wb`）则不会。Linux/macOS 下两者没有区别，但为了跨平台兼容性，**读写二进制数据时务必加上 `b`**。
# `fwrite`
`fwrite`函数用于把数据的二进制数据按块写入文件
## 语法
```c
size_t fwrite(
    const void *ptr,
    size_t size,
    size_t nmemb,
    FILE *stream
);
```
参数：

|参数|含义|
|---|---|
|`ptr`|要写入的数据地址|
|`size`|每个元素的字节数|
|`nmemb`|要写多少个元素|
|`stream`|文件流|
返回值：成功写入的元素的个数，不是字节数
# `fread`
`fread`函数用于从文件流中按块读取二进制数据
## 语法
```c
size_t fread(void* ptr,size_t size,size_t nmemb,FILE* stream);
```
参数：

| 参数       | 含义                              |
| -------- | ------------------------------- |
| `ptr`    | 数据读到哪里，即读取的元素会被写入到`ptr`指向的内存空间中 |
| `size`   | 每个元素的字节数                        |
| `nmemb`  | 最多读取多少个元素                       |
| `stream` | 文件流                             |
返回值：实际成功读取的元素个数，不是字节数
如果使用`fread`读取字符串，不会自动在字符串末尾增加结束符`'\0'`
另外要注意一下这里使用`fopen`时的`mode`参数，就要使用下面这两个模式

| 模式   | 含义    |
| ---- | ----- |
| `wb` | 二进制写入 |
| `rb` | 二进制读入 |
还有，这里`nmemb`表示的是**最多**读取多少个元素，也就是说实际读取的元素也可以小于这个数字
## 例1
假如我们先执行了
```c
int b[5] = {1,2,3,4,5};

FILE *p = fopen("a.txt","wb");

size_t m = fwrite(b,sizeof(int),5,p);
```
这里把数组`b`中的五个元素的二进制数据块写入了文件`a.txt`中
然后再执行
```c
int a[5];

FILE* fp = fopen("a.txt","rb");

size_t n = fread(a,sizeof(int),5,fp);
```
这时候又会把`a.txt`中的二进制数据按块读入数组`a`中
而`a.txt`的二进制数据就是根据数组`int b[5] = {1,2,3,4,5}`的二进制数据写入的
得到的结果就是：
```
a[0]的值为1
a[1]的值为2
a[2]的值为3
a[3]的值为4
a[4]的值为5
```
但是要注意，这里`a.txt`的内容一定不是
```
1 2 3 4 5
```
而是数组
```c
int b[5] = {1,2,3,4,5};
```
的二进制数据
后面`fread`做的事情就是把这个二进制数据读入数组`a`
最后，不要忘了执行
```c
fclose(p);
fclose(fp);
```
# `fseek`
移动文件流的读写位置
## 语法
```c
int fseek(FILE *stream, long offset, int origin);
```
## 参数

|参数|含义|
|---|---|
|`stream`|文件指针|
|`offset`|偏移量|
|`origin`|从哪里开始偏移|
在二进制模式（`rb`,`wb`）下，这里的偏移量的单位是字节
`origin`有三种：
```
SEEK_SET    //文件开头
SEEK_CUR    //当前位置
SEEK_END    //文件末尾
```
所以
```c
fseek(fp,10,SEEK_SET);
```
表示：从文件开头向后移动10个字节
```c
fseek(fp,5,SEEK_CUR);
```
表示：从当前位置向后移动5个字节
```c
fseek(fp,-3,SEEK_CUR);
```
表示：从当前位置向前移动3个字节
```c
fseek(fp,-4,SEEK_END);
```
表示：从末尾向前移动4个字节
## 返回值
如果移动成功，返回0
如果移动失败，返回非0
## 如果偏移量超过了末尾
假设文件只有 100 字节：
```c
fseek(fp, 200, SEEK_SET);
```
相当于想把位置移动到第 200 字节处。
### 如果后面读取
```
int ch = fgetc(fp);
```
因为当前位置已经在文件末尾之后，所以通常直接读取失败：
```
ch == EOF
```
此时可以：
```
feof(fp)
```
检查是否因为到达文件末尾。
### 如果后面写入
```
fseek(fp, 200, SEEK_SET);
fputc('A', fp);
```
在支持这种操作的普通文件系统上，文件会被扩展：
```
原文件：
0 ---------------- 100

seek后：
0 ---------------- 100 ---------------- 200
                                      ^

写入 A 后：
0 ---------------- 100 ---------------- 200 A
```
也就是文件长度会增长到至少 201 字节。
中间 `100 ~ 199` 这一段，在 POSIX 等常见系统上通常读出来是 `0`，而且文件系统可能把它实现成**稀疏文件**，不一定真的写入 100 个零字节。
不过这一点涉及操作系统行为，不应该单纯依赖 ISO C 认为所有平台都完全一样。
# `ftell`
取得目前文件流的读写位置
## 语法
```c
long ftell(FILE *stream);
```
## 参数
`stream`：文件指针
## 返回值
成功返回目前文件流读写位置
失败返回`-1L`
## 用来获取二进制文件的大小
```c
fseek(fp,0,SEEK_END);//把当前读写位置放在文件末尾

long size = ftell(fp);
```
假如`fp`指向的文件大小为100字节
那么
```
size的值为100
```
# `feof`
用于判断文件流是否达到文件末尾(EOF,End Of File)的函数
## 语法
```c
int feof(FILE *stream);
```
`stream`在这里是要检测的文件流指针，也就是`FILE *`
## 返回值
`feof`返回一个整数，这个整数的含义如下

| 返回值 | 含义        |
| --- | --------- |
| 非0  | 已经达到文件末尾  |
| 0   | 还没有达到文件末尾 |
例如：
```c
FILE *fp = fopen("test.txt","r");

if(fopen(fp))
{
	printf("文件结束\n");
}
```
## `feof`不会提前知道文件结束
实际上，`feof`本质是检查EOF标志位是否被设置，而这个标志位通常在一次读取失败后才设置的，这个EOF标志位是`FILE`结构体内的一个成员属性
假如说有一个文件`a.txt`
```txt
abc
```
如果执行下面这个代码
```c
FILE *fp = fopen("a.txt","w");

if(NULL == fp)
{
	printf("fopen error!\n");
	exit(1);
}

char ch;

while(!feof(fp))
{
	ch = fgetc(fp);
	printf("%c\n",ch);
}

fclose(fp);
```
第一次
```
abc
↑
```
读取`a`，EOF标志位未设置
第二次
```
abc
 ↑
```
读取`b`，EOF标志位未设置
第三次
```
abc
  ↑
```
读取`c`，EOF标志位未设置
第四次，尝试读取，发现读取失败，则设置EOF标志位，但是，这第四次依然会进入循环，这就会引发问题。`fgetc`读取到了EOF，EOF就是一个整型-1，然后被赋值给`ch`，而`ch`是`char`，并且大多数系统上的`char`都是无符号的，直接把-1赋值给`char`就会出现问题。
-1的补码为
```
11111111 11111111 11111111 11111111
```
截断之后赋值给`ch`，`ch`实际存储的值就是
```
0xFF
```
有些情况下都会打印出来乱码，也有可能什么都不显示
## `feof`不适合用来判断空文件
假设当前工作目录中已经存在一个空文件`empty.txt`
```c
FILE *fp = fopen("empty.txt","r");

if(NULL == fp)
{
	printf("fopen error!\n");
	exit(1);
}

if(feof(fp))
{
	printf("文件为空\n");
}
else
{
	printf("文件不是空\n");
}

fclose(fp);
```
我们知道，当执行`fopen("empty.txt","r")`时，会打开这个空文件`empty.txt`但是，默认情况下EOF标志位不会被设置，只有一次读取失败之后才会被设置。但是文件刚创建，根本没有被读取过，然后就直接利用判断标志位是否被设置来判断文件是否为空，结果就是因为标志位没有被设置直接被当成了非空文件。
如果想要正确判断文件是否为空，可以这样写
```c
FILE *fp = fopen("empty.txt","r");

if(NULL == fp)
{
	printf("fopen error!\n");
	exit(1);
}

fgetc(fp);

if(feof(fp))
{
	printf("文件为空\n");
}
else
{
	printf("文件不是空\n");
}

fclose(fp);
```
