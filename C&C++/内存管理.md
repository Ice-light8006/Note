## 1.硬盘（静态存储） VS内存（动态存储）的区别
硬盘断电数据能保留，内存断电数据不能保留
假如在硬盘的当前工作目录中有代码`hello.c`与利用这个代码编译好的程序`hello`
执行Linux命令`./hello`运行这个程序，实际上所做的第一步就是把这个程序从硬盘拷贝到内存中。
## 2. 为什么所有的编程都关注内存管理？
内存属于稀缺资源。尤其是嵌入式开发，内存管理尤为重要。因为大部分嵌入式设备上内存大小极小。
## 3. 编程过程中，内存管理主要做什么？
**防止内存泄漏**
>**内存泄漏**是指程序在动态分配内存（例如通过 `new`、`malloc`、`calloc` 等）之后，失去了对该内存的引用或未能及时释放，导致这块内存既不能被程序继续使用，也无法被操作系统回收，直到程序结束。
## 4. 如何防止内存泄漏
- 用户自己管理
	- 缺点：对用户的要求比较高（良好编码习惯、经验值）
	- 优点：开销小，实时性高
- 系统管理（GC：垃圾回收机制）
	- 优点：能够有效的防止内存泄漏
	- 缺点：开销大，实时性差，用户无法干预

# Linux虚拟地址空间
```text
高地址  ┌─────────────┐->0xFFFFFFFF
       │   内核空间   │ ← 用户态不可访问
       |             |
       ├─────────────┤->0xC0000000
       │   栈（向下） │  #栈空间是用户空间里最危险的，栈空间保存返回地址和局部变量，一旦发生缓
       |             |   冲区溢出，可能覆盖返回地址，导致控制流劫持，是安全漏洞的高发区。
       ├─────────────┤
       |      ↓      | 
       ├─────────────┤
       │   动态链接库 │
       ├─────────────┤
       |      ↑      | 
       ├─────────────┤
       │   堆（向上） |
       ├─────────────┤
       │   数据段     │ #bss段用来存放未初始化和初始化为0的全局变量/静态变量
       │   (BSS, 数据)│
       ├─────────────┤
       │   代码段     │
低地址  └─────────────┘

#这里内核空间为1GB，其余为3GB
```
栈空间保存的是局部变量和函数的形参
栈空间的特点：
- 先进后出
- 系统管理
堆保存的是`malloc`,`realloc`,`calloc`分配的空间
堆空间：
- 用户管理
- 先进先出
数据段保存的是未初始化的全局变量
数据段也有一个or段（这个or就是Only Read，只读），保存常量
数据段也有一个静态数据区，保存`static`标记的变量和全局变量
## 栈溢出覆盖返回地址
```text
正常栈布局（简化）：
高地址  ┌────────────┐
       │ 返回地址   │  ← func 结束后应该返回 main 中的位置
       ├────────────┤
       │ 局部数组 a │  ← 数组越界可能写入到返回地址的位置
低地址  └────────────┘
如果越界写入：
- 写入了函数地址 → 返回时跳转到该函数
- 写入了其他数据 → 返回时跳转到非法地址 → 崩溃
```
越界写入的例子：

```c
#include<stdio.h>

void test()
{
	printf("Hello world\n");
}

void func()
{
	int a[5];
	a[10] = test;
}

int main()
{
	func();
	return 0;
}

```
1. **主动写** `a[10] = test;`  
    把 `test` 函数的地址**作为整数**存到了越界的位置。
2. 那个位置**恰好**（由编译器的栈布局决定）是 `func` 的返回地址所在的内存。
3. 当 `func` 执行 `return` 时，CPU 从栈上弹出返回地址，此时拿到的不是原来的返回地址，而是你写进去的 `test` 地址，于是**跳转到 `test` 执行**。
## 借助栈帧解释
当程序执行函数调用时，编译器会为每个函数在栈上分配一块内存，称为**栈帧（Stack Frame）**。每个栈帧通常包含：
- **返回地址**：函数执行结束后，应该回到调用者的哪条指令继续执行。
- **局部变量**：函数内定义的自动变量（如 `int a[5]`）。
- **保存的寄存器**、**参数**（有时通过寄存器传递）等。
栈帧按函数调用顺序**依次压入**，函数返回时**弹出**。这就是“调用栈”名字的由来。
```text
高地址
       +-----------------+
       |   main 的栈帧     |
       +-----------------+
       |   func 的返回地址 |  ← 指向 main 中调用 func 的下一条指令
       +-----------------+
       |   (可能的对齐填充) |
       +-----------------+
       |   a[4]           |
       |   a[3]           |
       |   a[2]           |
       |   a[1]           |
       |   a[0]           |  ← 数组在栈上从低地址向高地址生长
       +-----------------+
低地址
```
- 如果你用 `a[10]` 写入，偏移量很可能到达 **返回地址** 所在的位置。
- 这就是为什么栈溢出能劫持控制流——它源于对**调用栈布局的精确理解**。

# 内存的分配方式
几个内存管理函数
- `malloc`
- `calloc`
- `realloc`
- `free`
## 1. `malloc` – 内存分配（未初始化、按字节分配）
### 函数原型
```c
void *malloc(size_t size);
```
### 功能
在堆上分配一块连续内存，大小为 `size` 字节。**内容不会初始化**，里面是未定义的垃圾值。
### 参数
- `size`：要分配的字节数（例如 `sizeof(int) * 10`）。
### 返回值
- 成功：返回指向分配内存起始地址的指针（`void*`）。
- 失败：返回 `NULL`。
### 示例
```c
int *p = (int*)malloc(5 * sizeof(int));
if (p == NULL) {
    // 处理分配失败
}
```
### 注意事项
- 分配的内存**未清零**，必须手动初始化。
- 分配后，若不再使用，必须调用 `free` 释放，否则造成**内存泄漏**。
- 对 `malloc` 返回的指针进行**强制类型转换**不是必须的（C 语言中 `void*` 可隐式转换为其他指针），但一些编译器或 C++ 编译器中需要。
- 如果`malloc`分配失败，那么会返回`NULL`空指针
---

## 2. `calloc` – 内存分配（初始化为零、按块分配）
### 函数原型
```c
void *calloc(size_t nmemb, size_t size);
```
### 功能
在堆上分配一块内存，用于存放 `nmemb` 个元素，每个元素大小为 `size` 字节（总大小 = `nmemb * size`）。**所有字节初始化为 0**。
### 参数
- `nmemb`：元素个数。
- `size`：每个元素的大小（字节）。

### 返回值
- 成功：返回指向分配内存起始地址的指针。
- 失败：返回 `NULL`。
### 示例
```
int *p = (int*)calloc(5, sizeof(int)); // 分配5个int，全部初始化为0
```
### 与 `malloc` 的区别

| 特性  | `malloc`  | `calloc`         |
| --- | --------- | ---------------- |
| 初始化 | 不初始化（垃圾值） | 全部初始化为 0         |
| 参数  | 一个：总字节数   | 两个：元素个数 + 单个元素大小 |
| 性能  | 稍快（不写零）   | 稍慢（需写零）          |
|     | 按字节分配     | 按块分配             |

### 注意事项
- 同样需要 `free` 释放。
- 若 `nmemb` 或 `size` 为 0，行为由实现定义（可能返回 `NULL` 或一个不可 dereference 的非空指针）。

---

## 3. `realloc` – 重新调整内存大小
### 函数原型
```c
void *realloc(void *ptr, size_t new_size);
```
### 功能
更改之前通过 `malloc`/`calloc`/`realloc` 分配的内存块的大小，变为 `new_size` 字节。**会尽量保留原有数据**（取新旧大小的较小值）。
### 参数
- `ptr`：指向之前分配的内存块的指针（若为 `NULL`，行为同 `malloc(new_size)`）。
- `new_size`：新的内存块大小（字节）。
### 返回值
- 成功：返回指向新内存块的指针（**可能与原地址相同，也可能不同**）。
- 失败：返回 `NULL`，**原内存块不变**（未被释放）。
### 示例
```c
int *p = (int*)malloc(5 * sizeof(int));
// ... 之后需要扩大
int *tmp = (int*)realloc(p, 10 * sizeof(int));
if (tmp == NULL) {
    // 处理失败，p 仍然有效
} else {
    p = tmp;
}
```
### 注意事项
- 如果 `new_size` 为 0 且 `ptr` 非 `NULL`，行为类似 `free(ptr)` 并可能返回 `NULL`（实现相关）。
- **绝对不要**直接写 `p = realloc(p, new_size);`，因为若 `realloc` 失败返回 `NULL`，会丢失原指针 `p`，导致原内存泄漏且无法释放。
- 扩展时，新增部分的内存**未初始化**（类似 `malloc`）。
- 缩小内存时，缩掉的部分会被释放，数据丢失。

---

## 4. `free` – 释放内存
### 函数原型
```c
void free(void *ptr);
```
### 功能
释放之前由 `malloc`、`calloc` 或 `realloc` 分配的内存块，将其归还给堆供后续分配使用。
### 参数
- `ptr`：指向要释放的内存块的指针（若为 `NULL`，`free` 什么都不做）。
### 返回值
无（`void`）。
### 示例
```c
int *p = (int*)malloc(10 * sizeof(int));
// ... 使用 p
free(p);    // 释放内存
p = NULL;   // 好习惯：避免悬空指针
```
### 注意事项
- **不能重复释放**同一块内存（未定义行为）。只能释放尚未释放的内存。
- 释放后原指针变成“悬空指针”，应将其设为 `NULL`，防止后续误用。
- 只能释放动态分配的内存，不能释放栈上或全局变量的地址。
- 释放部分内存（如只释放中间某段）是不允许的，必须整块释放。
---
## 总结对比表

| 函数        | 功能        | 初始化            | 参数个数       | 失败时           |
| --------- | --------- | -------------- | ---------- | ------------- |
| `malloc`  | 分配原始内存    | 不初始化           | 1（总字节）     | 返回 NULL       |
| `calloc`  | 分配并清零     | 全零             | 2（个数，大小）   | 返回 NULL       |
| `realloc` | 调整已分配内存大小 | 保留原数据，新增部分未初始化 | 2（原指针，新大小） | 返回 NULL，原内存不变 |
| `free`    | 释放动态内存    | —              | 1（指针）      | —             |
## 静态分配内存与动态分配内存
- 静态分配内存
	- 缺点：空间使用效率不高，有可能分配大了，浪费空间，分配小了，不够用
	- 优点：开销小（空间开销与访问开销），连续内存空间
- 动态分配内存
	- 优点：使用多少分配多少，空间使用效率提高
	- 缺点：开销大（空间开销、访问开销），空间不一定是连续的；容易造成内存碎片，造成内存浪费
## 几个内存管理函数的使用的典型例子
### 使用规范
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main()
{
    int* p = malloc(sizeof(int)*100);

    //一定要先判断内存是否分配成功
    if(NULL == p)
    {
        printf("malloc error!\n");
        goto err;
    }

    //malloc不会初始化分配的内存，一定要初始化
    memset(p,0,sizeof(int)*100);

    //然后可以正常使用这块内存
    *p = 10;
    printf("%d\n",*p);  //打印10

    //这块内存使用完之后一定要释放
    free(p);

    //释放之后一定要置空，free只是单纯告诉操作系统p指向的这一块内存没有被使用，可以被分配
    //此时p如果不置空就会变成悬空指针
    p = NULL;
err:
    return 0;
}
```
### 一个会引发段错误的代码
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main()
{
	char* str = malloc(sizeof(char)*100);
	if(NULL == str)
	{
		printf("malloc error!\n");
		exit(1);
	}
	memset(str,0,sizeof(char)*100);
	strcpy(str,"hello");
	
	while(*str!='\0')
	{
		str++;
	}
	
	//引发段错误
	free(str);
	str = NULL;
	
	return 0;
}
```
这里，在`while`循环内部，`str`被自增了，最终指向了字符串末尾的结束符，早已经不是最初`malloc`的返回值了。
记住，传给`free`的值只能是
- `NULL`
- `malloc`,`calloc`,`realloc`的返回值
如果`free(p)`接收的`p`不是`malloc`的返回值的话，这属于未定义行为，大多数编译器会报段错误
