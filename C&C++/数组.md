# 对数组的理解
- 数组是一个静态分配空间
- 数组所占内存空间是连续的，相邻索引的元素在实际内存中都是相邻的（这叫物理连续）额外要注意一下，`malloc`分配的内存不一定是物理连续的，假如你指定的长度没有那么长的内存了，那么`maoolc`会把很多小块的内存利用链表拼接起来
# 可变长数组
C99支持可变长数组，就是可以使用一个已经赋值的变量来初始化
```c
#include<stdio.h>

int main(int argv,char **argc)
{
	int n;
	scanf("%d",&n);
	int a[n];
	for(int i = 0;i<n;i++)
	{
		a[i] = i;
	}
	for(int i = 0;i<n;i++)
	{
		printf("a[%d]=%d\n",i,a[i]);
	}
	return 0;
}
```
但是要注意，不能在使用过程中以修改变量的值，来扩充数组的内存。例如这里，已经`int a[n]`定义过数组，之后如果再修改`n`的值，仅仅是把`n`这个变量的值修改了，数组的大小不会改变。
# 如何使用数组
实际操作中，更多采用的是定义时直接确定数组的长度。可以使用宏来表述数组的大小，提高代码移植性与可读性
下面介绍一个关于数组的一个非常重要的知识点**数组名的作用**
先以一维数组名为例
在大多数表达式中，一维数组名会**自动退化（decay）为指向首元素的指针**：
```c
#include<stdio.h>
int main(int argc,char **argv)
{
	int a[10];
	int *p = a;// a在表达式中退化为指向首元素的指针，等价于 &a[0]
}
```
但是，数组名是一个指针常量，不可以进行自增自减操作
```c
#include<stdio.h>
int main(int argc,char **argv)
{
	int a[10];
	a++;//错误
	a--;//错误
}
```
而普通指针支持自增(`++`)与自减(`--`)操作，这是数组名与普通指针不同的地方。
从键盘输入一个数组就有三种写法，如下代码所示
直接对`a[i]`取地址：
```c
int a[10];
for(int i = 0;i<10;i++)
{
	scanf("%d",&a[i]);
}
```
利用数组名`a`加操作数`i`得到`i`索引的元素对应的地址：
```c
int a[10];
for(int i = 0;i<10;i++)
{
	scanf("%d",a+i);
}
```
利用一个指针变量`p`存储数组`a`的首地址然后每次读取之后自增：
```c
int a[10];
int *p = a;
for(int i = 0;i<10;i++)
{
	scanf("%d",p++);
	//注意这里是p++，不是++p，否则会先对p自增然后再从键盘读入数据，这样会使数据整体向右偏移一个单位
}
```
# 数组给函数传参的注意事项
看这个代码
```c
#include <stdio.h>

void func(int a[100])
{
	printf("sizeof(a) = %d",sizeof(a));
}

int main(int argc,char **argv)
{
	int b[100];
	func(b);
	return 0;
}
```
很多人第一次是不是会以为函数`func`打印的结果为`sizeof(a) = 400`?
不，实际上输出为
```out
sizeof(a) = 4
```
但是这个数组明明长度为100，而一个`int`占4个字节，应该是100乘以4等于400，为什么是4呢？
这是因为在函数传参时，数组会退化为第0个元素的首地址，实际上上面的代码等价于
```c
#include <stdio.h>

void func(int *a)
{
	printf("sizeof(a) = %d",sizeof(a));
}

int main(int argc,char **argv)
{
	int b[100];
	func(b);
	return 0;
}
```
里面的参数无论写`int a[100]`或者`int a[1000]`还是多长，最终结果都是退化成整个数组的首地址，所以定义函数时如果形参有数组，参数写`int a[100]`和`int a[1000]`是完全一样的，没有任何区别，都等价于`int *a`
# 一维数组的地址
## 数组名的作用
数组名大多数情况下会退化为其首元素的地址
但并不是所有情况下都会退化为首元素的地址
```c
int a[5];
```
a本来的类型是
```c
int[5]
```
只不过大部分情况下会退化为指向首元素的地址
```c
int *
```
有些情况下并不会退化为首元素的地址，例如
```c
sizeof(a)
```
等价于
```c
sizeof(int[5])
```
下面这个代码
```c
printf("sizeof(a) = %d\n",sizeof(a));
printf("sizeof(int[5]) = %d\n",sizeof(int[5]));
```
输出结果是一样的，都是20
但是如果写
```c
printf("sizeof(a+0) = %d",sizeof(a+0));
```
这时候
如果环境为32位，打印结果为
```
sizeof(a+0) = 4
```
如果环境为64位，打印结果为
```
sizeof(a+0) = 8
```
因为数组名`a`参与了运算，就会发生退化，退化为了指向数组首元素的指针。
## `sizeof(*&a)`是多少
```c
&a
```
类型是：
```c
int (*)[5]
```
对它解引用：
```c
*&a
```
得到的又是整个数组，类型为：
```c
int[5]
```
所以：
```c
sizeof(*&a)
```
结果仍然是20：
```c
int a[5];

printf("%zu\n", sizeof(*&a));  // 20
```
## 一维数组的内存分布
先看这个代码
```c
#include <stdio.h>


int main(int argc,char **argv)
{
	int a[10];
	printf("&a[0] = %p\n",&a[0]);//数组首元素的地址
	printf("a = %p\n",a);//数组名，通常退化为首元素的地址
	pritnf("&a = %p\n",&a);//数组的地址
	return 0;
}
```
打印出来其实会发现三个结果是一样的。前两个大部分情况下是一样的，但是最后一个需要额外注意，它与前两个不一样（尽管具体数值一样）
假如我们定义一个数组
```c
int a[3];
```
假设其占用的内存如下
```
0x1000
0x1001
0x1002
0x1003
0x1004
0x1005
0x1006
0x1007
0x1008
0x1009
0x100a
0x100b
```
每个元素的情况如下
```
0x1000
0x1001
0x1002  a[0]
0x1003
------
0x1004
0x1005
0x1006  a[1]
0x1007
------
0x1008
0x1009
0x100a  a[2]
0x100b
```
`a[0]`占用的内存为0x1000到0x1003这一段内存
`a[1]`占用的内存为0x1004到0x1007这一段内存
`a[2]`占用的内存为0x1008到0x100b这一段内存
`a[0]`占的这四个地址的首地址0x1000作为`a[0]`的地址，即`&a[0] = 0x1000`，对于`a[1]`,`a[2]`也同理
而整个数组占用0x1000到0x100b这一段内存，这时候计算机会让整个数组的首地址0x1000作为数组的地址，即`&a = 0x1000`
## 加一操作上的不同
对单独一个地址进行加一操作，步长为1（不过C语言没有任何指针可以脱离类型存在，这样理解即可）
而对数组的一个元素的地址（`a[0]`或`a[1]`或`a[2]`）进行加一操作，步长就为`sizeof(int)`，即4
对数组的地址（`&a`）进行加一操作，步长就是这整个数组占用的内存长度，12
## 总结
从上面的表述可以完全看出，数组的地址`&a`其实代表了那12个字节的整体，而`&a[0]`或`a`（会退化为`&a[0]`）仅仅是代表了数组的第一个元素那四个字节。这就是数组的地址最大的不同
```c
a; //数组名，指针常量，保存数组首元素的地址
&a; //对数组名取地址，等于数组的地址
*(&a); //对一维数组的地址进行解引用，得到的是数组首元素的地址
```

# 数组指针
整型变量的地址用整型指针存，字符变量的地址用字符指针存
那么，数组的地址就用用数组指针变量存
**数组指针变量**是一个变量，保存的数据为数组的地址
定义一个长度为3的整型数组的数组指针`p`
```c
int (*p)[3];//整型数组指针变量，一个变量，保存的是地址，该地址是数组的地址，该数组是一个整型数组，有三个元素
```
假如有一个数组
```c
int a[3];
```
那么就可以这样初始化`p`
```c
p = &a;
```
也就有一个等式
```c
*p = a;
```
那么在读入数据的时候也可以这样写
```c
#include <stdio.h>

int main(int argc,char **argv)
{
	int a[3];
	int (*p)[3] = &a;
	for(int i = 0;i<3;i++)
	{
		scanf("%d",*p+i);//这里*p等价于a，其实就是a+i
	}
	return 0;
}
```
这里`[]`中的元素决定了你的数组的步长
```c
int (*p)[3];
```
所以初始化时一定要传入长度相同的数组的数组指针
另外，定义指针数组时，如果这样写
```c
int (*p)[]
```
`p`表达的意思是
>`p`是一个数组，指向一个数组，这个数组的长度未知

如果我们的代码这样写
```c
#include <stdio.h>

int main(int argc,char **argv)
{
	int a[3];
	int (*p)[] = &a;
	for(int i = 0;i<3;i++)
	{
		scanf("%d",*p+i);//这里*p等价于a，其实就是a+i
	}
	return 0;
}
```
也是合法的，但是这里`p`并不能根据`&a`自动推导出`p`的类型为`int (*)[5]`，其类型还是`int (*)[]`，即指向未知长度的数组的指针
这是合法的，编译器都会编译通过，但是会出一些问题
假如有
```c
int a[3];
int (*p)[] = &a;
```
如果写
```c
p++;//错误！
```
由于编译器不知道数组指针`p`指向的数组的长度为多少，自然就无法知道`p++`移动的步长是多少，就会发生错误
如果写
```c
sizeof(*p);//错误
```
同样，也是不知道`p`指向的数组长度为多少而引发的错误
## 数组指针只是一个指针
```c
int a[5];
int (*p)[5] = &a;
printf("sizeof(p) = %d",sizeof(p));
```
这个打印结果不是数组的长度20！
因为数组指针只是一个指针
如果环境为32位，打印结果为
```
sizeof(p) = 4
```
如果环境为64位，打印结果为
```
sizeof(p) = 8
```
# 二维数组
二维数组的基本定义
```c
int a[2][2];
```
对于带初始化的定义，不能省略列，可以省略行
```c
int a[][2] = {1,2,3,4};//省略行没有省略列，这是合法的
```
如果是
```c
int a[][2] = {1,2,3};
```
后面的数据个数不能整除2，那么会自动在后面补0
但是为什么有行而不省略列不可以呢
因为如果只知道行数不能确定唯一的数组，例如
```c
int a[2][] = {1,2,3,4};
```
这时候
```
1 2
3 4

1 2 3
4 0 0
```
会出现不同的情况
但是如果只知道列
```c
int a[][2] = {1,2,3,4};
```
这时候
```
1 2
3 4
```
只有这一种情况
所以这就是为什么只能省略行不能省略列
另外，直接写一个省略行的定义而不初始化也是会报错的
```c
int a[][2];//错误
```
## 二维数组的数组名的作用
```c
#include<stdio.h>

int main(int argc,char **argv)
{
	int aa[2][2] = {1,2,3,4};
	printf("aa = %p\n",aa);
	printf("aa+1 = %p\n",aa+1);
	printf("&a[0][0] = %p\n",&a[0][0]);
	printf("&a[0][0] + 1 = %p\n",&a[0][0]+1);
	return 0;
}
```
在我测试的环境下，输出为
```out
aa = 0061FF10
aa+1 = 0061FF18
&a[0][0] = 0061FF10
&a[0][0] + 1 = 0061FF14
```
可以发现`aa+1`与`aa`差了8个字节，而不是4个字节，这就可以印证这里`aa`不是首元素的地址
这个二维数组的内存分布如下
```
0x61FF10
0x61FF11
0x61FF12  a[0][0]
0x61FF13
--------
0x61FF14
0x61FF15
0x61FF16  a[0][1]
0x61FF17
--------
0x61FF18
0x61FF19
0x61FF1A  a[1][0]
0x61FF1B
--------
0x61FF1C
0x61FF1D
0x61FF1E  a[1][1]
0x61FF1F
```
`aa[0][0]`占据着内存0x61FF10到0x61FF13
`aa[0][1]`占据着内存0x61FF14到0x61FF17
`aa[1][0]`占据着内存0x61FF18到0x61FF1B
`aa[1][1]`占据着内存0x61FF1C到0x61FF1F
那么
```
&aa[0][0] = 0x61FF10
&aa[0][1] = 0x61FF14
&aa[1][0] = 0x61FF18
&aa[1][1] = 0x61FF1C
```
而二维数组`aa`可以看做由两个一维数组`a[0]`与`a[1]`构成的
可以视为：二维数组可以看做以一维数组为元素的数组
那么，`aa`退化为首元素的地址，在这里就是第一个一维数组的地址。
所以，对`aa`执行加一操作就跳到了下一个一维数组。
而`aa[0]`就是和第一个一维数组的数组名完全等效，使用时会退化为第一个一维数组的首地址
`aa[1]`就是和第二个第二数组的数组名完全等效，使用时会退化为第一个一维数组的首地址
## 总结
```c
int aa[2][2] = {1,2,3,4};
sizeof(aa); //这个数值为8
sizeof(aa+1); //这个数值为8
sizeof(aa[0]); //这个数值为8
sizeof(aa[1]); //这个数值为8
sizeof(&aa); //这个数值为16
```
在这几个表达式中
`aa`表示的是第一个一维数组的数组指针，步长为第一个一维数组的长度
`aa+1`表示的是第二个一维数组的数组指针
`aa[0]`表示的是第一个一维数组的首地址，等效于第一个数组的数组名
`aa[1]`表示的是第二个一维数组的首地址，等效于第二个数组的数组名
`&aa`表示的是整个二维数组的数组指针，一次加一操作步长为整个二维数组占用的字节大小（在这里为16）
由这些，就可以得到底层的寻址公式：
```
aa[i][j] = *(*(aa+i)+j)
```
（假设`a[0]`为第0个一维数组）`aa`首个一维数组的数组指针，`aa+i`得到第`i`个一维数组的数组指针，然后解引用`*(aa+i)`就得到了第`i`个数组，`*(aa+i)`等效于第`i`个数组的数组名，即第`i`个数组的首个元素的地址。而第`i`个数组的索引为`j`的元素就是`*(*(aa+i)+j)`
即：
```
aa:首个一维数组的地址
aa+i:第i个一维数组的地址
*(aa+i):第i个一维数组的首元素的地址
*(aa+i)+j:第i个一维数组的j索引上的元素的地址
*(*(aa+i)+j):第i个一维数组的j索引上的元素的数值
```
另外要注意这几个式子的区别：
```
aa  指针常量，保存的是首个一维数组的地址
&aa  二维数组的地址
*(&aa)=aa  对二维数组的地址取值等于首个一维数组的地址
*aa  首个一维数组的首个元素的地址
```
# 三维数组
```c
int a[2][2][2] = {{1,2,3,4},{5,6,7,8}};
```
对每个下标的解释
```
第一个下标：表示第几个二维数组
第二个下标：表示二维数组中的第几个一维数组
第三个下标：表示一维数组中的第几个元素
```
例如
```
a[1][0][0]
```
表示：
```
第1个二维数组的第0个一维数组的第0个元素
```
## 三维数组的遍历方式
最简单的遍历方式
```c
for(int i = 0;i<2;i++)
{
	for(int j = 0;j<2;j++)
	{
		for(int k = 0;k<2;k++)
		{
			printf("a[%d][%d][%d] = %d\n",i,j,k,a[i][j][k]);
		}
	}
}
```
利用数组名+解引用运算符：
```c
for(int i = 0;i<2;i++)
{
	for(int j = 0;j<2;j++)
	{
		for(int k = 0;k<2;k++)
		{
			printf("a[%d][%d][%d] = %d\n",i,j,k,*(*(*(a+i)+j)+k));
		}
	}
}
```
## 三维数组的数组名的作用
```
a
```
代表三维数组中首个二维数组的地址
对于
```c
int a[2][2][2] = {{1,2,3,4},{5,6,7,8}};
```
执行
```
a+1
```
会跳16个字节，因为aaa会退化为第一个二维数组的数组指针，aaa+1得到的就是第二个二维数组的数组指针，这个操作的步长为16个字节
```
*a
```
等价于：三维数组中首个二维数组的首个一维数组的数组指针。等价于首个二维数组的数组名退化为首个二维数组的首个元素的地址
```
**a
```
等价于：三维数组中首个二维数组的首个一维数组的首元素的地址
```
***a
```
等价于：三维数组中首个二维数组的首个一维数组的首元素的值
```
&a
```
三位数组的地址
```
*(&a) = a
```
对三维数组的地址取值等于首个二维数组的地址
对`*(*(*(a+i)+j)+k)`的解释
```
a：三维数组中首个二维数组的地址
a+i:三维数组中第i个二维数组的地址
*(a+i)：三维数组中第i个二维数组的首个一维数组的地址
*(a+i)+j：三维数组中第i个二维数组的第j个一维数组的地址
*(*(a+i)+j)：三维数组中第i个二维数组的第j个一维数组的首元素的地址
*(*(a+i)+j)+k：三维数组中第i个二维数组的第j个一维数组的第k个元素的地址
*(*(*(a+i)+j)+k)：三维数组中第i个二维数组的第j个一维数组的第k个元素的内容
```
对于更高维度的数组，就是纯粹的一层一层往下套娃，没有任何区别
# 再谈数组名的作用
现在我们看完了一维数组、二维数组、三维数组和它们的数组名的作用
我们通过一个使用`scanf`从键盘录入字符串的例子来再谈数组名的作用
看下面这三个字符数组
```c
char str1[100];
char str2[2][100];
char str3[2][2][100];
```
首先我们要先明白，如果要用`scanf`录入一个数组，传入的第二个参数要求是对应字符数组的首元素的地址
如果要用`scanf`对这三个字符数组进行录入，写法如下：
对于第一个数组
```c
scanf("%s",str1);
```
这里`str1`会自动退化为这个数组的首元素的地址
对于第二个数组
```c
for(int i = 0;i<2;i++)
{
	scanf("%s",*(str2+i));
}
```
这里`str2`会退化为首元素的地址，对这个二维数组来说就是首个一维数组的地址，然后再加`i`就得到第`i`个一维数组的地址，之后再对`str2+i`进行解引用（相当于对数组的地址解引用）就得到了第`i`个数组的首元素的地址
对于第三个数组
```c
for(int i = 0;i<2;i++)
{
	for(int j = 0;j<2;j++)
	{
		scanf("%s",*(*(str3+i)+j));
	}
}
```
这里`str3`得到首元素的地址，对这个三维数组来说就是首个二维数组的地址，`str3+i`得到的就是第`i`个二维数组的地址，然后`*(str3+i)`得到的就是第`i`个二维数组的首元素的地址，即第`i`个二维数组中的首个一维数组的地址，然后`*(str3+i)+j`得到的就是第`i`个二维数组的第`j`个一维数组的地址，然后`*(*(str3+i)+j)`得到的就是第`i`个二维数组的第`j`个一维数组的首元素的首地址

>事实上，在C语言中，除了在 `sizeof` 和 `&` 操作符之后，数组名在表达式中总是会自动退化（隐式转换）为**指向其首元素的指针**。

再强调一个已经说过了的细节，防止混淆，就是对数组名取地址是什么作用？
对于
```c
int a[10];
```
`a`会退化为数组首元素的地址类型为`int*`，而`&a`表示的是数组的地址，类型为`int(*)[10]`
# 数组指针变量的应用场景
先回顾一下数组指针的定义方式
```c
int(*p)[3];
```
这里`p`是一个变量，保存的是地址，该地址是数组的地址，该数组是一个整形数组，有三个元素。
事实上，数组指针与直接用数组名，实际指向的地址是一样的，只是两者的步长不一样，数组名直接退化为首元素的地址，实际上步长为一个元素的大小，而数组指针的步长为整个数组的大小。那么问题就来了，数组指针究竟有什么用呢？
数组指针最大的作用就是函数传参
对于一维数组作为函数参数传参，就是直接退化为首元素的地址，不再赘述
主要看二维数组作为函数参数传参：
```c
#include <stdio.h>

void func(int(*p)[2])
{
	for(int i = 0;i<2;i++)
	{
		for(int j = 0;j<2;j++)
		{
			printf("arr[%d][%d] = %d",i,j,*(*(p+i)+j));
		}
	}
}

int main(int argc,char **argv)
{
	int arr[2][2] = {{1,2},{3,4}};
	func(arr);
}
```
这时候函数`func`调用时传入数组名`arr`作为函数参数，会自动退化为首元素的地址，对于这个二维数组，首元素的地址就是首个一维数组的数组指针，而首个一维数组的数组指针的类型就是`int(*)[2]`，所以这里我们的形参应该定义为`int(*p)[2]`（这里变量`p`可以替换为别的名字）
# 指针数组
指针数组就是一个数组，这个数组里保存的都是指针
指针数组的定义方式
```c
int *p[3];
```
`p`是一个数组，存储的类型为整型指针变量
把它和数组指针的定义放在一起进行比较，防止混淆
```c
int *p1[3];    //指针数组的定义
int (*p2)[3];  //数组指针的定义
```
在刚定义指针数组时，如果不进行初始化，系统会随机分配一块栈上的残留数据给它，这就会出现野指针，也就是整个指针数组上的所有值全都是野指针。例如：
```c
#include <stdio.h>

int main(int argc,char **argv)
{
	int *p[3];
	for(int i = 0;i<3;i++)
	{
		scanf("%d",p[i]);//段错误！
	}
	return 0;
}
```
直接这样写就会产生段错误。因为`p[i]`是野指针。
合法的写法：
```c
#include <stdio.h>
#include <stdlib.h>

int main(int argc,char **argv)
{
	int *p[3];
	for(int i = 0;i<3;i++)
	{
		p[i] = (int*)malloc(sizeof(int));
		scanf("%d",p[i]);
	}
}
```
先给`p[i]`分配内存，这样`p[i]`里存储的就不是野指针了，进而不会引发段错误。
另外，用完之后要释放内存并置空
```c
#include <stdio.h>

int main(int argc,char **argv)
{
	int *p[3];
	for(int i = 0;i<3;i++)
	{
		pi[i] = (int*)malloc(sizeof(int));
		scanf("%d",pi[i]);
	}
	
	for(int i = 0;i<3;i++)
	{
		printf("pi[%d] = %d\n",i,*(pi[i]));
		//用完之后要释放并置空
		free(p[i]);
		p[i] = NULL;
	}
}
```
再看这个例子：
```c
char *pi[3] = {"hello1","hello2","hello3"};
```
这里`pi[0]`指向`"hello1"`的首字符的地址，`pi[1]`指向`"hello2"`的首字符的地址，`pi[2]`指向`"hello3"`的首字符的地址。
但是这里要注意，这三个字符串是常量，不可以修改。
## 指针数组名作为形参给函数传参
```c
#include <stdio.h>

void func(char **p)
{
}

int main(int argc,char **argv)
{
	char *p[3] = {"hello1","hello2","hello3"};
	func(p);
}
```
我们可以这样理解：**数组名退化为指向其首元素的指针**，首元素是`char *`，所以退化后是二级指针`char **`。

>一维数组传参时用其存储的元素类型的指针来接
>二维数组传参时用一维数组指针来接
>三位数组传参时用二维数组指针来接
>.....
>指针数组传参时用指针的指针来接

所以，当以后看到一个函数的形参为一个二级指针的时候，那么传过来的参数有可能是一个**指针的地址**，也有可能是一个**指针数组**

再回顾一下指针数组使用注意事项：
- 局部指针数组里元素都是野指针；需要分配空间
- 用完之后要释放空间并置空
