# RC522 学习复盘

> 学习目标：不依赖现成驱动，从 SPI 底层开始，理解 RC522 的工作原理，能够自己分析数据手册并实现驱动。

---

# 一、整体学习路线

整个学习过程可以分成五个阶段：

```
SPI通信
    │
    ▼
RC522寄存器操作
    │
    ▼
RC522命令控制
    │
    ▼
RC522通信流程（ToCard）
    │
    ▼
ISO14443A协议（REQA、Anticollision……）
```

学习到这里，我已经跨过了前四个阶段。

真正开始困难的是第五阶段，因为它已经不是 RC522 芯片本身，而是 RFID 通信协议。

---

# 二、第一阶段：SPI 控制 RC522

## 学习内容

实现了：

```cpp
RC522_WriteReg()

RC522_ReadReg()
```

理解：

```
STM32
   │SPI
   ▼
RC522寄存器
```

真正控制 RC522，本质就是：

```
读寄存器
写寄存器
```

---

## 最大收获

以前认为：

> "RC522 很复杂。"

后来发现：

其实它就是：

```
一个 SPI 外设
+
很多寄存器
```

和 OLED、Flash 没有本质区别。

---

# 三、第二阶段：寄存器操作

实现：

```cpp
RC522_SetBitMask()

RC522_ClearBitMask()
```

自己写出了：

```cpp
value |= mask;

value &= ~mask;
```

理解：

为什么：

```
SetBitMask
```

必须：

```
Read

↓

OR

↓

Write
```

而不是直接写。

同样理解了：

```
ClearBitMask
```

为什么必须：

```
Read

↓

AND

↓

Write
```

---

## 重要理解

寄存器经常：

```
一个字节

不同bit

表示不同功能
```

不能直接覆盖整个寄存器。

---

# 四、第三阶段：RC522命令

学习：

```
CommandReg
```

理解：

```
CommandReg

bit0~3

Command

bit4

PowerDown

bit5

RcvOff
```

这里提出了一个很重要的问题：

> "直接写低四位，不会把高四位覆盖吗？"

最终理解：

命令寄存器属于：

```
Command字段
```

发送命令：

```
WriteReg(CommandReg, Command);
```

而不是：

```
SetBitMask()
```

---

## 软件复位

实现：

```cpp
RC522_Reset()
{
    RC522_WriteReg(CommandReg, PCD_SoftReset);
}
```

理解：

```
SoftReset

属于命令

不是状态位
```

---

# 五、第四阶段：天线

```
TxControlReg
```

理解：

```
Tx1RFEn

Tx2RFEn
```

提出问题：

> 为什么设置为1，而不是0？

最终理解：

```
打开天线

就是开启两个发射驱动
```

实现：

```cpp
RC522_AntennaOn()

RC522_AntennaOff()
```

# 六、第五阶段：FIFO

这是整个学习过程最大的转折点。

最开始疑惑：

```
连续写FIFODataReg

不会覆盖前面的数据吗？
```

后来自己推导出了：

```
FIFO

内部维护：

读指针

写指针
```

真正理解：

```
Write FIFODataReg

↓

写入当前位置

↓

写指针自动++

```

同时：

```
FlushBuffer

不是清数据

而是：

把读写指针复位
```

这是整个学习过程最重要的一次理解。

---

# 七、第六阶段：ToCard()

这是整个驱动的核心。

自己一步一步推导出了：

```
Flush FIFO

↓

写FIFO

↓

Transceive

↓

等待完成

↓

检查错误

↓

读取FIFO

↓

Idle
```

最终实现：

```cpp
RC522_ToCard()
```

---

## 通信流程

```
MCU

↓

FIFO

↓

Command=Transceive

↓

RC522编码

↓

天线发送

↓

卡片响应

↓

FIFO

↓

MCU读取
```

第一次真正理解：

RC522其实就是：

```
FIFO

+

编码器

+

解码器
```

# 十、第一次真正理解"天线"

提出问题：

> "FIFO传输到天线是什么意思？"

最终理解：

```
FIFO中的字节

↓

ISO14443A编码

↓

高频磁场波形

↓

天线发射
```

RC522不是把字节发出去。

而是：

```
字节

↓

数字调制

↓

磁场
```

---

# 十一、BitFramingReg

这是整个学习过程中第二个难点。

理解：

```
TxLastBits

RxAlign

StartSend
```

最大的收获：

```
TxLastBits

不是：

0=0bit

而是：

0=8bit
```

这是很多初学者都会误解的地方。

---

# 十二、REQA

第一次接触协议层。

学习：

```
REQA

0x26
```

理解：

为什么：

```
TxLastBits

必须等于7
```

因为：

```
REQA

最后一个字节

只发送7bit
```

实现：

```cpp
RC522_Request()
```

---

## 第一次开始区分

```
RC522芯片

↓

负责发送
```

和：

```
ISO14443A

↓

规定发送什么
```

---

# 十三、开始理解协议

最大的认知变化：

以前认为：

```
RC522

决定通信
```

后来理解：

真正决定通信的是：

```
ISO14443A
```

RC522只是：

```
按照FIFO

把数据发出去
```

例如：

```
REQA

SEL

UID

SAK

CRC
```

全部属于协议。

不是RC522。
