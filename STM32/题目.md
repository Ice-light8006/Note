# 1.什么是嵌入式？
嵌入式系统是一种**专用的计算机系统**，它被设计用来执行特定的功能，通常作为更大设备或系统的一部分。与我们日常使用的通用计算机（如台式机、笔记本）不同，嵌入式系统通常“嵌入”到它所控制的设备内部，用户往往感知不到它的存在。

# 2.什么是嵌入式操作系统？
嵌入式操作系统是专门为嵌入式系统设计的操作系统软件，它负责**管理和控制嵌入式硬件资源**，并为上层应用程序提供运行环境和服务接口。与桌面或服务器操作系统不同，嵌入式操作系统通常针对**特定应用场景**进行了深度裁剪和优化，追求在有限资源下的高效、可靠运行。
简单来说，如果把嵌入式硬件比作"身体"，那么嵌入式操作系统就是"神经系统"——它协调各个硬件部件协同工作，并让应用程序能够有序运行。

# 4.什么样的操作系统可以做为嵌入式操作系统？
嵌入式操作系统通常需要具有可裁剪性、实时性、低功耗、小体积、高可靠性、硬件适配灵活
- **可裁剪性**：能根据硬件资源灵活裁剪功能模块，小到几十KB内存的微控制器也能运行
- **实时性**：能在确定的时间范围内响应外部事件，分为硬实时（绝对不能超时）和软实时（偶尔超时可接受）
- **低功耗支持**：支持多种低功耗模式（如休眠、待机），适配电池供电场景
- **小体积**：内核和系统占用空间小，能装入有限的Flash和RAM中
- **高可靠性**：长时间运行不崩溃，具备故障恢复机制
- **硬件适配灵活**：能移植到不同架构的处理器上（ARM、RISC-V、x86等）
如果资源受限（如MCU），可以选择RTOS（FreeRTOS、RT-Thread、VxWorks等）
如果资源较丰富（如MPU），可以选择嵌入式Linux、HarmonyOS、WIndows loT等
 - **FreeRTOS** —— 最流行的轻量级实时操作系统
- **RT-Thread** —— 国产开源实时操作系统
- **VxWorks** —— 航空航天、国防领域常用
- **Zephyr** —— Linux 基金会维护的物联网实时操作系统
- **Linux** —— 开源操作系统，广泛应用于桌面、服务器、嵌入式等场景


# 5.嵌入式处理器有哪些？
嵌入式处理器（Embedded Processor）是指**专门用于嵌入式系统中的计算核心**，特点通常是：低功耗、实时性强、成本低、体积小。它不像 PC 的 CPU 追求通用高性能，而是针对控制、通信、采集、驱动等任务优化。
## 1. 微控制器 MCU（Microcontroller Unit）
这是最常见的嵌入式处理器。
特点：
- CPU + RAM + Flash + 外设集成在一个芯片里
- 功耗低
- 成本低
- 实时控制能力强
- 适合控制类应用
结构：
```
        MCU
 ┌────────────────┐
 │ CPU            │
 │                │
 │ Flash          │
 │ SRAM           │
 │ GPIO           │
 │ ADC            │
 │ PWM            │
 │ UART/I2C/SPI   │
 │ Timer          │
 └────────────────┘
```
典型产品：
### ARM Cortex-M 系列（主流）
STMicroelectronics 的 STM32：
- STM32F1：入门经典
- STM32F4：高性能 MCU
- STM32H7：高性能 Cortex-M7
应用：
- 智能车
- 无人机控制器
- 电机控制
- 家电
- 工业控制
其他：
- NXP Semiconductors LPC 系列
- Texas Instruments MSP430
- Microchip Technology PIC 系列
- AVR（Arduino 常用）
---

# 8、运行时语言 vs 解释语言 vs 静态语言
## 解释语言
核心：源代码通常由解释器直接读取并执行，而不是先生成机器码。
最典型的解释语言就是Python
## 静态语言
核心：变量类型在运行前就确定
例如C++
```cpp
int a = 5;
```
在运行前就已经确定了变量`a`是整型，绝对不能给`a`赋值别的类型的变量，例如不能把字符串赋值给变量`a`
而Python
```python
a = 5
a = "Hello"
```
这都是合法的，因为Python运行时才决定：
```
第一次：
a → int对象

第二次：
a → **string对象**
```
这叫**动态类型语言**（Dynamically Typed Language）
## 运行时语言
核心：程序运行需要一个额外的运行时环境（Runtime Environment）。
例如Java程序运行时需要Java虚拟机（JVM）

## 支持结构化编程

# 10、什么是面向结构的编程？
将一个复杂程序拆分成多个功能明确的小模块（函数），通过顺序、选择、循环三种基本结构组织程序。
它的关键思想包括：
- **三种基本控制结构**：顺序执行、条件分支、循环迭代。禁止使用 `goto` 语句进行无条件跳转，因为 `goto` 会导致程序流程混乱，形成所谓的"面条代码"（spaghetti code）。
- **自顶向下，逐步求精（Top-Down, Stepwise Refinement）**：先设计整体框架，再逐步细化每个模块的实现细节。这是结构化编程非常重要的设计方法论。
- **模块化**：将程序拆分为功能独立、边界清晰的模块（函数/过程），每个模块完成一个明确的子任务。你说的"每个功能封装成函数"就属于这一层。
- **单入口单出口**：每个函数或代码块应只有一个入口和一个出口，保证程序流程可预测、易追踪。

# 11、为什么嵌入式开发选择C语言？
嵌入式开发选择 C 语言主要因为 C 语言具有较强的硬件控制能力和较高的执行效率。C语言提供指针机制，可以直接访问内存地址，通过操作寄存器实现对硬件的控制。同时 C 语言编译后生成机器码，运行效率高、资源占用少，适合资源受限的嵌入式系统。此外，C语言具有较好的可移植性和成熟的开发生态，因此成为嵌入式开发的主流语言。

# 12、什么是RTOS？
**RTOS（Real-Time Operating System，实时操作系统）**，就是**能够保证任务在规定时间内完成的操作系统**。
简单来说：
> RTOS 是一种专门用于嵌入式系统的操作系统，它负责管理 CPU、任务、内存、通信等资源，并保证关键任务能够及时响应。

假设一个智能小车：
需要同时执行：
- 电机控制（每 1ms 更新一次）
- 读取传感器（每 10ms）
- 蓝牙通信（不定时）
- 显示屏刷新（每 100ms）
如果不用 RTOS：
你可能写一个大循环：
```
while(1)
{
    motor_control();
    read_sensor();
    bluetooth();
    display();
}
```
问题：
- 某个任务执行时间长，会阻塞其他任务
- 代码越来越复杂
- 很难保证实时性
---
使用 RTOS：
可以把功能拆成多个任务：
```
任务1：电机控制任务
周期：1ms
优先级：最高

任务2：传感器任务
周期：10ms

任务3：通信任务
优先级：中

任务4：显示任务
优先级：低
```
RTOS负责调度：
```
CPU
 |
 |-- 电机任务
 |
 |-- 传感器任务
 |
 |-- 通信任务
 |
 |-- 显示任务
```

# 14、C vs C++ VS 汇编（移植性差）
汇编语言最接近硬件，可以直接操作CPU指令和寄存器，执行效率高，但是严重依赖具体硬件平台，移植性差，开发难度大。
C语言在效率、可移植性和硬件控制能力之间取得了较好的平衡，可以通过寄存器映射等方式操作硬件，是嵌入式开发的主流语言。
C++是在C基础上增加了面向对象、泛型编程和标准库，提高了大型项目的软件组织能力，适合复杂嵌入式系统和应用开发。

# 18、各种数据类型的字节长度及取值范围？
C标准并没有严格规定每个数据类型的字节长度
对于整型，只规定了每个整型之间的大小关系：
```c
sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)
```
而对于浮点类型
```c
float
double
long double
```
C标准没有规定`sizeof`必须满足什么关系，只规定了每个浮点类型的要求
```c
float ≤ double ≤ long double
```
注意，这里比较的不是表示数字范围的大小，而是表示数字精度的大小
但是这些仅仅是C标准的规定，实际上大部分计算机所实现的数据类型的字节长度和取值范围是下面这样的

| 数据类型          | 字节长度               | 取值范围                                                  |
| ------------- | ------------------ | ----------------------------------------------------- |
| `char`        | 1                  | -128-127                                              |
| `short`       | 2                  | -32768-32767                                          |
| `int`         | 4                  | $-2^{31}{\textasciitilde}2^{31}-1$                    |
| `long`        | 4（Win），8（Linux）    | 4字节与`int`一致<br>8字节为$-2^{63}{\textasciitilde}2^{63}-1$ |
| `long long`   | 8                  | $-2^{63}{\textasciitilde}2^{63}-1$                    |
| `float`       | 4                  | ±3.4×10³⁸（约 6~7 位有效数字）                                |
| `double`      | 8                  | ±1.7×10³⁰⁸（约 15~16 位有效数字）                             |
| `long double` | 8（MSVC）/16（GCC 常见） | 精度高于`double`                                          |

# 19、sizeof、strlen区别
一句话概括：
- `sizeof`：计算变量或类型占用的内存大小（字节数）
- `strlen`：计算字符串的长度（字符数）（不包括结尾的结束符）
另外，`sizeof`是一个关键字，不是一个函数。而`strlen`就是一个函数

# 20、补码的作用？
让计算机只用一套加法电路，就能同时完成加法和减法，并且只有一个 0。

- **原码**：最符合人的直觉——最高位表示正负。
- **反码**：补码产生过程中的过渡形式，现在几乎不直接使用。
- **补码**：最符合计算机硬件设计——**让减法变成加法，让所有整数都能用统一的电路处理。**

# 21、C语言内存空间布局？
我们平时说的 **C 语言内存空间布局**，实际上指的是**现代操作系统（Linux、Windows）中，一个 C 程序运行时的虚拟地址空间布局**。
```
高地址
┌──────────────────────┐
│       内核空间        │  （用户程序不能访问）
├──────────────────────┤
│         栈（Stack）   │  ↓ 向低地址增长
│                      │
├──────────────────────┤
│      空闲区域（Heap）  │
│         堆（Heap）    │  ↑ 向高地址增长
├──────────────────────┤
│   BSS 段（未初始化）   │
├──────────────────────┤
│ Data 段（已初始化）    │
├──────────────────────┤
│ ROData（只读数据）     │
├──────────────────────┤
│ Text（代码段）         │
└──────────────────────┘
低地址
```

# 22、局部变量和全局变量的区别？
**局部变量（Local Variable）** 和 **全局变量（Global Variable）** 最大的区别体现在 **作用域、生命周期、存储位置** 三个方面。
## 作用域
局部变量只能在自己所在的代码块里使用，全局变量整个源文件都可以访问
## 生命周期
局部变量：进入其所在的代码块时创建，离开该代码块时销毁。
全局变量：程序开始执行，创建；程序退出，销毁。
## 存储位置
局部变量通常放在栈区内
全局变量通常放在Data段或者BSS段

# 23、static关键字的作用？（语法作用，应用场景）
对局部变量加上static修饰，不改变作用域，但是会把生命周期延长到整个程序结束，并且只初始化一次。如果没有显式初始化，则初始化为0
对全局变量加上static修饰，会使得这个全局变量只能在当前.c文件被访问。
对函数加上static修饰，会使得这个函数只能在当前.c文件内被调用。可以在多人协作时对自己的工具函数加上static防止和别人的工具函数冲突
