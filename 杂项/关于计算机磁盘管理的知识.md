首先区分三个概念：
- 固件
- 固件启动模式
- 分区表

|概念|是什么|例子|
|---|---|---|
|**固件（Firmware）**|主板上的底层软件|BIOS、UEFI|
|**启动模式（Boot Mode）**|固件采用哪种方式启动操作系统|Legacy、UEFI|
|**分区表（Partition Table）**|硬盘如何划分分区|MBR、GPT|
# 固件
固件（Firmware）是存储在主板 Flash 芯片中的低层软件，负责计算机上电后的硬件初始化和启动操作系统。
对于固件，可以这样理解：
```
硬件（Hardware）
      ↑
   固件（Firmware）
      ↓
软件（Software）
```
例如：
- CPU 是硬件。
- Windows 是软件。
- 主板里的 BIOS/UEFI 存在一块 Flash 芯片里，上电就能运行，它不是操作系统，也不是普通应用程序，所以称为**固件**。
# 启动模式
在WIndows环境下，按下Win+R按键，然后输入msinfo32，按下回车，进入系统信息页面
>这里这个msinfo32，ms就是Microsoft，info就是information。这个命令实际的意思是Microsoft system information 32

在系统摘要页面里，找打一个项目“BIOS模式”，Windows 将其显示为"BIOS 模式"，实际上表示当前系统采用的固件启动方式。
使用UEFI固件的计算机使用UEFI启动模式或者Legacy启动模式
使用BIOS固件的计算机使用Legacy启动模式
目前绝大部分计算机的固件是UEFI，所以启动模式都是UEFI。
# 分区表
分区表的作用就是一句话：
> 硬盘分区表格式，用于记录磁盘上各个分区的位置、大小、类型等信息。UEFI 或操作系统都会读取它。

计算机的启动过程：
```
按下电源
      │
      ▼
UEFI 固件启动
      │
      ▼
初始化 CPU、内存、显卡等硬件
      │
      ▼
读取 GPT 分区表
      │
      ▼
找到 EFI System Partition（ESP）
      │
      ▼
根据启动项找到对应的 .efi 文件
      │
      ▼
运行 bootmgfw.efi（Windows）
或 grubx64.efi（Linux）
      │
      ▼
加载操作系统
```
EFI 系统分区（ESP）用于存放各操作系统的启动程序（`.efi` 文件）。UEFI 根据启动项找到对应的 `.efi` 文件并执行。
不过要注意，虽然我们在文件资源管理器看不到EFI分区。但是实际上，EFI 分区和 C 盘、D 盘是**同一级别的磁盘分区**，只是 Windows 默认把它隐藏了，不给它分配盘符，所以你平时看不到。
对于WIndows的计算机，还有一个分区叫Recovery分区
该分区存储的内容主要是 **Windows 恢复环境（Windows Recovery Environment，WinRE）**。可以把它理解成：
> **一个"迷你版 Windows"。**

里面有一个核心文件：
```
winre.wim
```
这是一个 Windows 镜像文件，里面包含了一个精简的 Windows 系统。

# 启动顺序
一句话来说
> 启动顺序（Boot Order）就是 UEFI 在开机时，按照什么顺序去寻找可以启动的设备。
## 还有一种方法：启动菜单（Boot Menu）
其实现在很多人**根本不会改 Boot Order**。
而是：
开机不停按：
```
F12
```
（不同品牌可能是 F11、Esc、F8 等。）
会出现：
```
Boot Menu

请选择：

Windows Boot Manager

UEFI Kingston USB

Ubuntu

Network Boot
```
你只需要：
```
UEFI Kingston USB
```
按 Enter。
**这一次**从 U 盘启动。
下一次开机：
仍然：
```
Windows
```
所以：
> Boot Menu 是**临时选择**。

> Boot Order 是**永久默认顺序**。

# 文件系统
如何直观的理解文件系统？我们可以这样看一个硬盘
如果把硬盘比作一个大仓库，那么：
- 分区（Partition）是仓库里的某一个区域（A区、B区、...等）
- 文件系统（NTFS、FAT32等）是每个区域专属的管理员和管理规则
- 文件夹是货架
- 文件是货物
如果没有文件系统，操作系统根本不知道：
- 文件放在哪里
- 哪些空间已经用了
- 哪些空间还是空闲
- 文件叫什么名字
- 谁有权限访问
所以，文件系统就是管理磁盘数据的一套规则
## 文件系统的作用
### 管理文件名
假如在你的D盘的根目录下，有这些文件
```
movie.mp4
photo.jpg
test.cpp
```
实际上磁盘里没有“movie.mp4”，“photo.jpg”，“test.cpp”这几个字
文件系统维护了类似这样的一个表

|文件名|起始位置|
|---|---|
|movie.mp4|Block 100|
|photo.jpg|Block 300|
|test.cpp|Block 800|
### 管理磁盘空间
假如一个分区有10000个数据块
哪些用了？
哪些没用？
这时候文件系统会维护：
```
Block 1 没用
Block 2 占用
Block 3 没用
.....
Block 9999 占用
Block 10000 没用
```
这时候操作系统就知道了哪些数据块被占用哪些数据块没有被占用
### 管理目录
目录实际上就是树结构，例如
```
D
│
├── 游戏
│     ├── LOL.exe
│     └── config.ini
│
└── 视频
      └── a.mp4
```
文件系统就会维护这个树结构
### 管理权限
假如当前WIndows操作系统的用户列表如下
```
Administrator

Users

Everyone

Ice_light
```
Administrator对某一个文件有什么权限？
Users对某一个文件有什么权限？
Everyone对某一个文件有什么权限？
Ice_light对某一个文件有什么权限？
这些都靠文件系统来记录
### 管理时间
在某一个文件的右键属性里
```
创建时间

修改时间

访问时间
```
这些时间就是文件系统维护的
### 防止数据损坏
突然断电：
```
正在复制 50GB 文件
```
如果没有保护：
```
文件可能直接废了。
```
现代文件系统都有各种恢复机制。
例如：
日志（Journal）
校验（Checksum）
事务（Transaction）
## 什么是FAT
FAT 是：
> **File Allocation Table**

> **文件分配表**

它是最古老、最经典的文件系统之一。
它的思想特别简单。
例如：
```
一个文件：

movie.mp4

大小：

10MB
```
磁盘：
```
Block

1
2
3
4
5
6
7
8
...
```
文件可能存成：
```
Block2

↓

Block8

↓

Block10

↓

结束
```
FAT 就维护这样一张表：

|Block|下一块|
|---|---|
|2|8|
|8|10|
|10|EOF|

读取文件：
```
Block2

↓

Block8

↓

Block10

↓

结束
```
像链表一样。
所以：
FAT 本质就是：
> **一张记录每个块"下一个块是谁"的表。**

## 常见的文件系统
| 文件系统  | 常见平台                | 最大单文件 | 日志  | 权限  | 典型用途            |
| ----- | ------------------- | ----- | --- | --- | --------------- |
| FAT32 | Windows、Linux、macOS | 4 GB  | ❌   | ❌   | 老设备、U盘、兼容性要求高   |
| exFAT | Windows、Linux、macOS | 非常大   | ❌   | ❌   | 大容量 U 盘、SD 卡    |
| NTFS  | Windows             | 非常大   | ✅   | ✅   | Windows 系统盘、数据盘 |
| ext4  | Linux               | 非常大   | ✅   | ✅   | Linux 系统盘       |
| XFS   | Linux               | 非常大   | ✅   | ✅   | 大文件、高性能服务器      |
| Btrfs | Linux               | 非常大   | ✅   | ✅   | 快照、校验、现代存储      |
