FreeRTOS的调度算法可以分为抢占式调度和协作式调度，抢占式调度又分为带时间片的抢占式调度和不带时间片的抢占式调度
# 简单介绍一下这两个调度算法
- 抢占式调度（Preemptive Scheduling）：调度器总是选择最高优先级的任务来执行，当高优先级的任务就绪时当前任务会立刻被抢占
- 协作式调度（Cooperative Scheduling）：调度器同样优先选择更高优先级的任务来执行，但是当高优先级的任务就绪时，只有当前任务主动让出CPU资源，才会重新调度
# 通过修改配置文件指定调度算法
在CubeMX的工程文件中的`FreeRTOSConfig.h`头文件中，有这个宏定义
```c
#define configUSE_PREEMPTION
```
如果这个宏定义为1，则使用抢占式调用，如果设置为0，则使用协作式调度
# 时间片
## 什么是时间片
时间片（Time Slicing）能够让优先级相等的任务之间获得近似相等的执行时间
注：时间片是建立在优先级相同的任务的基础上的，下面叙述的所有东西都是在优先级相同的两个任务的基础上进行的
比如说我们目前有任务A和任务B
如果启用时间片，假设一个时间片是1ms
那么程序就会执行1msA，然后再切换到任务B执行1ms，然后再回到A执行1ms......以此往复。但是，**不保证每个任务实际运行时间严格相等**。
如果关闭时间片，那么程序会在下面三种情况发生切换：
- 当前任务调用 `vTaskDelay()`，或等待队列等资源而进入阻塞状态。
- 当前任务主动调用 `taskYIELD()` 请求调度。
- 开启抢占时，更高优先级任务变为就绪状态。
## 通过配置文件指定调度算法
在CubeMX的工程文件中的`FreeRTOSConfig.h`头文件中，有这个宏定义
```c
#define configUSE_TIME_SLICING
```
如果这个宏的值为1，则开启时间片机制，如果这个宏的值为0，则关闭时间片机制
