# 任务的四种状态
首先，在FreeRTOS中，任务要么在运行，要么没有在运行。所以我们很自然的可以把任务分为运行状态和非运行状态。
但是实际上，FreeRTOS中对非运行状态进行了细分，分为了三种子状态：就绪状态、阻塞状态、暂停状态
所以，任务的四种状态有如下四种
- 运行状态（Running State）
- 就绪状态（Ready State）
- 阻塞状态（Blocked State）
- 暂停状态（Suspened State）
下面这个表是对每个状态的概述

| 状态   | 作用                                  |
| ---- | ----------------------------------- |
| 运行状态 | 被调度器选中，正在由单片机的CPU执行它的任务代码           |
| 就绪状态 | 等待被执行（也就是说这个任务已经满足了被执行的条件，但是还没有轮到它） |
| 阻塞状态 | 因等待先决条件（等待超时或者等待事件）而主动放弃执行权         |
| 暂停状态 | 吊用`vTaskSuspend()`使其不能被调度器选中        |

A、B、C、D、E、F这六个任务类比为六个人，这六个人共享一个饮水机，这个饮水机就可以类比为CPU，而这六个人共享这个饮水机，即A、B、C、D、E、F共享一个CPU的资源
A正在接水，所以任务A处于运行状态
B和C紧跟着后面在排队，一旦CPU有资源可以利用，则就会开始执行任务B和C。这里B和C的状态就是就绪状态
D进入了饮水器的黑名单，无论什么时候任务D都不会被调度器选中。直到程序员手动解除了暂停状态。这就是暂停状态
E刚喝了水，他准备10分钟之后再喝水。所以，在“10分钟过后”这个事件发生之后，E就会进入就绪状态只要饮水器可用就会去接水。所以这就是阻塞状态，要等待的事件就是”10分钟过去“。一旦这个事件发生则进入就绪状态
F没有杯子，他再等他买的杯子到了。在“他买的杯子到了”这个事件发生之后，F就会进入就绪状态。这也是阻塞状态，要等待的事件就是“买的杯子到了”。一旦这个事件发生则进入就绪状态
