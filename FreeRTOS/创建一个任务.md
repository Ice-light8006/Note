# 点灯程序示例
看下面这个点灯程序
```c
void LED_Loop_Task(void *argument)
{
    while(1)
    {
        LED_On();
        vTaskDelay(pdMS_TO_TICKS(1000));
        LED_Off();
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```
如果我们直接在`main`函数中直接执行这个函数，那么这个函数会直接占用整个CPU阻塞整个程序。如果我们还想再执行其它任务就会变得困难
这时候就可以利用FreeRTOS，FreeRTOS通过创建一个任务，利用任务执行这个函数体
FreeRTOS提供了下面这个函数
```c
BaseType_t xTaskCreate( TaskFunction_t pvTaskCode,
						const char * const pcName,
						unsigned short usStackDepth,
						void *pvParameters,
						UBaseType_t uxPriority,
						TaskHandle_t *pxCreatedTask);
```
这个函数用来创建一个任务，然后把函数作为这个任务的执行体，任务加入到FreeRTOS的任务调度器进行调度
每个参数的意义如下
- `TaskFunction_t pvTaskCode`：要添加的任务的函数的函数名
- `const char* const pcName`：给你创建的这个任务起的名字，为一个字符串
- `unsigned short unStackDepth`：栈深度
- `void *pvParameters`：传给任务函数的参数
- `UBaseType_t uxPriority`：优先级，数值越大优先级越高
- `TaskHandle_t *pxCreatedTask`：保存任务句柄，如果不需要你可以传`NULL`
这个栈深度可以理解为：给这个任务准备多大的运行空间，栈是任务运行时使用的一块RAM。
任务执行函数时，需要临时保存一些东西，例如：
- 局部变量、局部数组
- 调用其它函数时需要保存的信息，例如返回位置
- 任务切换时需要保存的CPU寄存器信息
例如，你的 LED 任务正在执行：
```c
LED_On();
vTaskDelay(pdMS_TO_TICKS(1000));
LED_Off();
```
调用 `vTaskDelay()` 后，LED 任务暂停，CPU 去执行其他任务。FreeRTOS 会保留 LED 任务的执行现场，等它再次运行时，从原来暂停的位置继续执行。
**每个任务都有自己的栈，用来保存各自运行时需要的数据。**
注意这个栈和函数调用栈不一样！这个栈是任务的栈，不是函数的栈
事实上：
>栈深度，就是这块栈能容纳多少个 `StackType_t` 元素。

那么就有对应关系：

|传给 `xTaskCreate()` 的栈深度|实际栈大小|
|---|---|
|128|512 字节|
|256|1024 字节|
|512|2048 字节|
利用这个函数，可以这样写：
```c
TaskHandle_t LEDTaskHandle = NULL;
xTaskCreate(LED_Loop_Task,"LED_Loop_Task",512/sizeof(StackType_t),NULL,24U,&LEDTaskHandle);
```
这时候就创建了一个任务，这个任务执行的内容就是函数`LED_Loop_Task`
而这个`512/sizeof(StackType_t)`就是栈深度，一般使用`512/sizoef(StackType_t)`就够了。如果不够可以再调节
而第四个参数`NULL`，则会作为`void LED_Loop_Task(void *argument)`的值传进去
而这个任务优先级，其取值范围为`0U`到`configMAX_PRIORITIES-1`,这个`configMAX_PRIORITIES`是一个在头文件`FreeRTOSConfig.h`中定义的宏
然后这个任务本身的信息就被整理成了一个句柄保存到了我们创建的变量`LEDTaskHandle`中，以后如果我们想要操作这个任务，都需要通过这个句柄来操作
FreeRTOS提供了下面几个用来操作任务的函数
```c
// 暂停任务的执行
void vTaskSuspend(TaskHandle_t xTaskToSuspend);

// 恢复已经暂停的任务
void vTaskResume(TaskHandle_t xTaskToResume);

//删除任务
void vTaskDelete(TaskHandle_t xTaskToDelete);
```
另外，介绍一下下面这个函数
```c
void vTaskDelay(const TickType_t xTicksToDelay);
```
它的作用是：让当前任务主动进入阻塞状态一段指定的时间，从而让出 CPU 的使用权。
参数`xTicksToDelay`的含义：当前任务需要阻塞的 Tick 数量
例如
```c
vTaskDelay(100);
```
意思是：当前任务阻塞100个时钟节拍
但是这里是时钟节拍，如果我们想要换算成ms，可以利用FreeRTOS提供的宏换算
```c
pdMS_TO_TICKS()
```
比如
```c
vTaskDelay(pdMS_TO_TICKS(1000));
```
这个会把1000ms转换成对应的节拍数，从而实现阻塞1000ms
