# Motor1：MG513 GMR 编码器电机调试流程

适用硬件：**MG513 GMR、12 V、减速比 1:30、500 PPR 编码器**，使用用户提供资料对应的四路智能电机驱动板。用户已确认电机接到 **Motor1**。本流程先由电脑通过驱动板 Type-C 串口调试，再接入 STM32F103RCT6。

**当前状态：**已确认接入 Motor1；电源类型、实际轮径、COM 号和固件版本尚未收到确认，暂未收到实际转动或编码器数据。文中的数值示例与预期现象不代表已经实测通过。

目标顺序：通信正常 → 参数读回正确 → 编码器有反馈 → 正反转与停机正常 → 低速闭环稳定。

## 0. 先准备好停止指令

调试过程中，以下指令让四路 PWM 输出归零：

```text
$pwm:0,0,0,0#
```

首次测试固定好电机，让轮子架空。出现异常转速、持续不转但电流明显上升、明显发热或反馈异常时，先发送停止指令；串口失效时切断电机电源。

本流程中的“小 PWM 起步、逐级增加、先停车再反转”为台架调试建议。

## 1. 核对 Motor1 接线和供电

在断电状态下，按功能核对以下连接：

| MG513 GMR 电机端 | 驱动板 Motor1 端 | 作用 |
| --- | --- | --- |
| 电机 M+ | M1+ | 动力输出 |
| 电机 M- | M1- | 动力输出 |
| 编码器 VCC | 3V3 | 编码器 3.3 V 供电 |
| 编码器 GND | GND | 编码器电源地与信号参考地 |
| 编码器 A | H1A | A 相反馈 |
| 编码器 B | H1B | B 相反馈 |

M1- 是受控动力输出端，不能当作 GND 使用。编码器电源接 3V3，不能接电机的 12 V。六针线束按信号定义确认，不凭插头形状或线色判断兼容。

电机的 12 V 动力电源接到驱动板专门的电源输入端，核对正负极。Type-C 数据线用于本次电脑通信，不能代替电机需要的 12 V 动力供电。

驱动板简介所列输入范围为 5-12 V。若使用电池，应核对满电电压；例如 3S 锂电池满电为 12.6 V，不能直接依据“标称 11.1 V”认定满足该资料的范围。

**本步完成标准：**动力与编码器接线已核对，供电类型及电压已记录，电机固定、轮子架空。

## 2. 连接电脑并设置串口助手

1. 用支持数据传输的 Type-C 线连接驱动板和电脑。
2. 打开设备管理器中的“端口（COM 和 LPT）”，通过插拔对照找到新增的 COM 口。
3. 打开资料包中的串口助手 UartAssist，选中对应 COM 口。
4. 设置下表参数并打开串口。

| 项目 | 设置 |
| --- | --- |
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 / None |
| 硬件流控 | 无 / None |
| 发送模式 | ASCII / 文本 |
| HEX 发送 | 关闭 |
| 配置指令循环发送 | 关闭 |

每条命令以 `$` 开头、以 `#` 结束。下文代码块中的命令要**每次复制一行、单独点击发送**；不把整段命令一次发出，也不把说明文字或反引号一起发送。

**本步完成标准：**对应 COM 口能够打开。没有 COM 口时，先检查数据线、USB 连接和串口驱动。

## 3. 停机并确认通信

依次单独发送：

```text
$pwm:0,0,0,0#
$upload:0,0,0#
$read_flash#
```

| 命令 | 作用 |
| --- | --- |
| `$pwm:0,0,0,0#` | 四路 PWM 输出归零 |
| `$upload:0,0,0#` | 关闭反馈上报，方便查看配置回复 |
| `$read_flash#` | 查询保存的电机参数和固件信息 |

预期：接收窗口出现固件版本、电机类型、死区、编码器线数、减速比、轮径、PID 等信息，具体字段名称以当前固件为准。保存这份原始读回内容。

如果 `$read_flash#` 完全没有回复，先排查 COM 号、串口是否打开、115200 8N1、ASCII 发送、数据线及供电，不继续发运动指令。

注意：文档说明 `$pwm` 和 `$spd` 运动指令不返回 OK；是否通信成功，以查询或配置回复判断。

**本步完成标准：**能够读到 `$read_flash#` 的实际返回内容。

## 4. 配置 MG513 GMR 参数

以下设置对应本流程的 **A→H1A、B→H1B** 接法。电机停止时逐条发送，每条配置等待成功回复后再继续：

```text
$mtype:2#
$mline:500#
$mphase:30#
$deadzone:0#
```

| 命令 | 含义 |
| --- | --- |
| `$mtype:2#` | 按厂家规定选择 A 对 A、B 对 B 的类型配置；界面名称为“310” |
| `$mline:500#` | 编码器内部轴每圈、单相 500 个完整方波周期 |
| `$mphase:30#` | 减速比为 30 |
| `$deadzone:0#` | 初次调试暂时关闭启动死区补偿 |

`mline` 填 **500**，不填四倍频后的 2000，也不填输出轴每圈的 60000。

默认死区值为 1600，说明书称 PWM 控制会叠加死区值。因此先关闭补偿，避免把小指令值误当成小输出。后续根据实际启动与低速表现再校准，不直接照搬其他电机的补偿值。

配置完成后再次查询：

```text
$read_flash#
```

| 参数 | 本轮预期读回值 | 实际值 |
| --- | --- | --- |
| 电机类型 | 2 | 待填 |
| 编码器线数 | 500 | 待填 |
| 减速比 | 30 | 待填 |
| 死区补偿 | 0 | 待填 |
| 轮径 | 以当前读回值记录，闭环前改为实际值 | 待填 |

这些配置参数会断电保存；正常运行时不要在循环中反复写入。首次调试先保留现有 PID，修改 PID 会使板卡重启。

**本步完成标准：**线数 500、减速比 30、类型 2、死区 0 均读回正确。若 500 无法正确保存，先核对固件兼容性，不进入速度闭环。

## 5. 检查编码器反馈

先上报 10 ms 窗口内的计数：

```text
$upload:0,1,0#
```

预期收到 `$MTEP:…#`，四个值依次对应 M1、M2、M3、M4。当前重点观察**第一个数**：

- 静止时应接近 0。
- 轻转输出轴时应有变化；减速箱难以反拖时不硬拧，改在下一步低 PWM 转动中检查。
- 正反向转动时，计数正负方向应相反。

例如，下面只是格式示例，不是当前实测值：

```text
$MTEP:300,0,0,0#
```

它表示 Motor1 在对应 10 ms 窗口内计数为 300，不是 300 rpm。10 ms 是计数统计窗口，不保证串口包严格每 10 ms 到达。

如果需要核对每圈计数，切换为累计上报：

```text
$upload:1,0,0#
```

接收格式为 `$MAll:…#`。记录输出轴沿同一方向转一圈的起止值，按四倍频及标称减速比计算，绝对差应接近：

```text
500 × 4 × 30 = 60000 计数 / 输出轴圈
```

也可累计多圈后取平均。不要通过 `$read_flash#` 或恢复出厂来清零累计值，直接计算起止差即可。

驱动板资料主要展示霍尔编码器，未明确承诺 500 线 GMR 的最高输入频率。60000 是应核验的理论值，不表示该板已经实测确认采用此口径。计数口径或稳定性异常时先排查，不把它直接带入速度环。

## 6. 开环测试：正转、停止、反转

本步前提：通信正常，类型、线数、减速比和死区已经读回确认。反馈上报可切回：

```text
$upload:0,1,0#
```

### 6.1 小正向输出

```text
$pwm:200,0,0,0#
```

只有 Motor1 接收非零输出。短时观察是否启动和第一个编码器数值的方向，然后归零：

```text
$pwm:0,0,0,0#
```

如果 200 不足以启动，先归零，再逐级试 400、600。每次短时观察后归零，不持续让电机通电却不转；仍不转时先检查动力电源、动力线和驱动输出，不直接跳到最大值。

### 6.2 停稳后测试反向

若 200 已能正常启动，停稳后可试：

```text
$pwm:-200,0,0,0#
```

如果实际稳定启动值更大，改用已验证的较小启动值的负值。短时观察后再次停止：

```text
$pwm:0,0,0,0#
```

### 6.3 方向与停机验收

| 项目 | 应观察到的现象 |
| --- | --- |
| 正向 PWM | 电机向一个方向转动，编码器反馈方向与板卡闭环约定一致 |
| 负向 PWM | 转动方向相反，编码器反馈方向也相反 |
| PWM 全零 | 动力输出归零，电机停止或自然减速停止 |

正向 PWM 对应负反馈、反馈恒为 0 或方向不随反转变化时，先归零，检查编码器相位接法、类型配置以及反馈是否与 Motor1 配对，不继续闭环。排查时不交换编码器 VCC/GND。

**本步完成标准：**能够可控地正转、停机、反转，编码器反馈随转动合理变化。

## 7. 低速闭环测试

本步前提：实际轮径已确认，原始计数和反馈方向均已核对。轮径未确认或尚未装轮子时，先完成前面的开环与编码器检查，暂不照抄轮径示例。

### 7.1 设置实际轮径

轮径单位为毫米。**只有实际轮径为 70 mm 时**，才发送以下示例；其他轮径应替换为实际数值：

```text
$wdiameter:70#
```

用 `$read_flash#` 检查轮径读回是否正确。

### 7.2 打开速度上报并给低速目标

逐条发送：

```text
$upload:0,0,1#
$spd:50,0,0,0#
```

含义：Motor1 目标轮缘速度为 **+50 mm/s**，其他通道目标为 0。反馈格式为 `$MSPD:…#`，第一个值为 Motor1 的速度。

50 mm/s 不是 50 rpm。轮径为 70 mm 时，按下式计算约为 13.6 rpm：

```text
输出轴 rpm = 轮缘速度(mm/s) × 60 / [π × 轮径(mm)]
```

先观察能否平稳启动和接近目标，再停车。低速稳定后才逐步提高目标，例如试 100 mm/s；不同时改动多个参数。

### 7.3 停车及反向

调试时先发送：

```text
$pwm:0,0,0,0#
```

停稳后，可用低速负目标测试反向：

```text
$spd:-50,0,0,0#
```

测试后再次发送 PWM 全零。

如果突然加速、明显振荡、持续不启动或方向不符合预期，先停止并核对原始计数、线数、减速比、轮径与反馈方向。默认 PID 不代表已针对 500 线 GMR 调好，不靠盲目增大 PID 或死区来处理异常。

### 7.4 两种零指令的区别

| 指令 | 含义 |
| --- | --- |
| `$spd:0,0,0,0#` | 目标速度为零，PID 继续工作，受到扰动时可能输出纠正力 |
| `$pwm:0,0,0,0#` | PWM 输出归零；不保证特定芯片电气上的完全滑行状态 |

零速 PID 不等于绝对位置保持，也不能替代硬件停止手段。资料没有明确说明通信失联自动停机时限，不能依赖拔掉 USB 自动停车。

**本步完成标准：**低速正反向可控，反馈接近目标，停机有效，无明显振荡、异常电流或温升。

## 8. 结束测试与接入 STM32

结束本轮测试时，逐条发送：

```text
$pwm:0,0,0,0#
$upload:0,0,0#
```

确认停止，保存串口日志，关闭串口并切断动力电源。更改接线时保持断电。

电脑验证通过后，F103RCT6 通过 USART2 发送相同 ASCII 命令：

| F103RCT6 | 驱动板 |
| --- | --- |
| PA2 / USART2_TX | RX2 |
| PA3 / USART2_RX | TX2 |
| GND | GND |

两端串口保持 115200 8N1。核心板按其规定供电，已独立供电时不直接并联另一 5 V 电源。控制端切换为 F103 后，避免电脑和主控同时向板卡发送指令。

采用板载速度闭环时，编码器接驱动板，由板卡完成测速和 PID；F103 负责目标速度、反馈接收、任务控制及停机逻辑。首次程序上电先输出全零，再进入明确的测试状态。厂家完整演示会自动切换多种运动状态，应先改为本流程的单路低速测试。

电脑串口助手用于开发台架测试；正式比赛应由车载程序按规则自主控制。

## 9. 常见异常排查

| 现象 | 优先检查 |
| --- | --- |
| 设备管理器没有 COM 口 | Type-C 是否为数据线、USB 连接、串口驱动 |
| COM 口打不开 | 是否选错端口，是否被另一个串口程序占用 |
| `$read_flash#` 无回复 | COM 号、串口参数、ASCII 发送、完整的 `$…#`、供电 |
| 配置有回复，PWM 不转 | 12 V 动力电源是否接入，M1+/M1- 是否正确，当前 PWM 是否足够启动 |
| 电机转，反馈一直为 0 | 编码器 VCC/GND、H1A/H1B、线束接触、动力与反馈是否同属 Motor1 |
| 反馈方向错误 | 实际 A/B 接法、类型配置、动力极性与编码器方向的对应关系 |
| 线数 500 无法读回 | 实物固件是否支持该参数范围，实际指令是否被正确解析 |
| 闭环速度比例明显异常 | 500 线、30 倍减速、实际轮径、倍频计数口径和速度单位 |
| 低速抖动或突然加速 | 先停机，检查反馈方向、计数质量、死区和 PID，不直接提高增益 |
| 高速丢计数 | 信号质量、接线、电源、固件输入频率与采码能力；降速后对照核验 |
