# Motor1：MG513 GMR 编码器电机调试流程

更新日期：2026-11-01。

适用硬件：**MG513 GMR、12 V、减速比 1:30、500 PPR 编码器**，使用用户提供资料对应的四路智能电机驱动板，电机接到 **Motor1**，主控为 **STM32F103RCT6**。当前 `Motor_Test` 工程使用 **USART1，PA9/TX、PA10/RX**。

本文分为两部分：第一部分为初始化，结合本次抖动问题更新；第二部分为电机控制，保留用户粘贴版本中第 5—11 节的原文。

# 第一部分：初始化

## 0. 本次调试结论与初始化目标

本次已获得的实际信息：

- 主控发送 `$spd:500,0,0,0#` 时，电机断续抖动；电脑串口助手直接发送同一命令时也抖动。
- 调整前的查询回包显示：固件 **1.7.3**，电机类型 **2**，编码器线数 **11**，减速比 **30**，死区 **1600**，保存轮径 **67 mm**，PID 为 **0.8、0.06、0.5**。
- 按 `$mline:500#`、`$deadzone:0#` 调整后，用户反馈电机可以正常运行。
- 配置后的完整查询回包、实际轮径、COM 号、电源实际电压与限流状态、定量转速和累计计数结果仍待记录。

**本次需要记住的两项设置：编码器线数为 500；死区补偿当前采用 0。** 500 来自这台电机的编码器规格，0 是本次排查采用的死区设置，后续可按实际起步和带载表现标定。

初始化的目标是：接线及供电正确 → 串口通信正常 → 驱动板保存的参数与电机匹配 → 读回核对 → 进入第二部分的电机控制测试。

调试前先准备好四路 PWM 输出归零指令：

```text
$pwm:0,0,0,0#
```

固定好电机，让轮子架空。发生异常加速、明显发热、持续不转但电流上升或反馈异常时，先停止输出；串口失效时切断动力电源。以下起步及限流设置属于台架调试建议。

## 1. 核对 Motor1 接线和供电

在断电状态下，按信号定义核对六根电机线：

| MG513 GMR 电机端 | 驱动板 Motor1 端 | 作用                     |
| ---------------- | ---------------- | ------------------------ |
| 电机 M+          | M1+              | 动力输出                 |
| 电机 M-          | M1-              | 动力输出                 |
| 编码器 VCC       | 3V3              | 编码器 3.3 V 供电        |
| 编码器 GND       | GND              | 编码器电源地与信号参考地 |
| 编码器 A         | H1A              | A 相反馈                 |
| 编码器 B         | H1B              | B 相反馈                 |

M1- 是受控动力输出端，不能当作 GND。编码器供电接 3V3；按功能核对线束，不凭线色或插头形状判断兼容。

**12 V 电源接驱动板的动力电源输入端。电机的两根动力线已经通过 M1+/M1- 取得受控供电，不需要再把另一组 12 V 直接接到电机上。** Type-C 数据线用于电脑通信，不能代替电机动力电源。

单个 Motor1、架空低速首次调试，可调直流电源可从 **12.0 V、限流 1.0 A** 起步。这是本项目的初始调试建议，不是电机运行时必须达到的电流，也不保证覆盖所有启动、带载或多电机工况。记录实际设置，并观察运行时电源是否保持 CV；若持续进入 CC、输出电压下降或板卡重启，先停机检查接线、机械阻力与供电余量。

驱动板简介所列输入范围为 5—12 V。改用电池时核对满电电压；3S 锂电池满电为 12.6 V，接入前需确认实物版本的允许输入范围。

当前主控与驱动板的串口连接如下：

| STM32F103RCT6 当前工程 | 驱动板串口接口 |
| ---------------------- | -------------- |
| PA9 / USART1_TX        | RX2            |
| PA10 / USART1_RX       | TX2            |
| GND                    | GND            |

两端 TX/RX 交叉连接、共地；供电按各板的电源接口要求接入。

**串口编号说明：**驱动板上的 TX2/RX2 是驱动板自己的串口标识，不要求主控也使用 USART2。第二部分第 8 节按要求保留了厂家 USART2（PA2/PA3）示例原文；你当前 `Motor_Test` 工程实际使用 USART1（PA9/PA10），接线以本节为准。

**本步完成标准：**动力线、编码器线及主控串口已对应核对；电机固定，供电设置已记录。

## 2. 连接电脑并设置串口助手

1. 用支持数据传输的 Type-C 线连接驱动板和电脑。
2. 在设备管理器的“端口（COM 和 LPT）”中，通过插拔对照找到对应 COM 口。
3. 打开串口助手，选中该端口，按下表设置。

| 项目             | 设置         |
| ---------------- | ------------ |
| 波特率           | 115200       |
| 数据位           | 8            |
| 停止位           | 1            |
| 校验位           | 无 / None    |
| 硬件流控         | 无 / None    |
| 发送模式         | ASCII / 文本 |
| HEX 发送         | 关闭         |
| 配置指令循环发送 | 关闭         |

每条命令以 `$` 开头、以 `#` 结束。下文命令要**每次复制一行、单独发送**，不要将整段命令、说明文字或反引号一起发送。配置命令等待成功回复后再发下一条。

使用电脑调试时，避免主控同时向驱动板发送控制指令。

## 3. 停机、查询并保存原始参数

依次单独发送：

```text
$pwm:0,0,0,0#
$upload:0,0,0#
$read_flash#
```

| 命令             | 作用                                             |
| ---------------- | ------------------------------------------------ |
| `$pwm:0,0,0,0#`  | 四路 PWM 输出归零                                |
| `$upload:0,0,0#` | 关闭连续上报，方便查看配置回包；此命令本身不停车 |
| `$read_flash#`   | 查询已保存参数和固件信息                         |

本次抖动排查时，实际收到的配置如下，**这是调整前的原始记录**：

```text
read_flash:OK!
Motor_Version:1.7.3
Motor_type:2
Dead_Zone:1600
Pulse_Line:11
Pulse_Phase:30
wheel_diameter:67.000
P:0.800  I:0.060  D:0.500
```
这些值的含义如下

| 字段               | 当前值    | 含义                                              |
| ---------------- | ------ | ----------------------------------------------- |
| `read_flash:OK!` | —      | 查询成功，驱动板正常返回配置；不代表参数一定配置正确                      |
| `Motor_Version`  | 1.7.3  | **电机驱动板内部固件版本**，与 STM32 主控程序的版本无关               |
| `Motor_type`     | 2      | 厂家编号为“310”的电机控制类型。按手册，当前 **A→H1A、B→H1B** 的接法选 2 |
| `Dead_Zone`      | 1600   | **小输出补偿值**，用于帮助电机克服摩擦起转，允许范围 0～3600             |
| `Pulse_Line`     | 11     | **内部电机轴转一圈，编码器单相产生的完整方波周期数**                    |
| `Pulse_Phase`    | 30     | **减速比**。这里表示内部电机轴约转 30 圈，减速箱输出轴转一圈              |
| `wheel_diameter` | 67.000 | **车轮直径 67 mm**，用于把转速换算成轮缘线速度                    |
| `P`              | 0.800  | 比例系数，根据当前速度误差产生调节作用                             |
| `I`              | 0.060  | 积分系数，累积速度误差，帮助消除长期存在的速度偏差                       |
| `D`              | 0.500  | 微分系数，根据误差变化趋势进行调节，帮助改善超调和振荡                     |

其中，`Pulse_Line:11` 与 MG513 GMR 的 500 线规格不匹配。其他参数相同时，按 11 线计算会使速度换算产生约 `500/11 ≈ 45.5` 倍的比例偏差，速度环可能反复增减输出。这是本次明确需要纠正的配置。

`Dead_Zone:1600` 是厂家默认补偿值，本次排查同时将其设为 0。两项调整后用户反馈运行正常；该结果不代表所有负载、速度下的 PID 和死区均已完成标定。

若 `$read_flash#` 完全没有回复，先检查 COM 口、115200 8N1、ASCII 发送、接线和供电。手册说明 `$pwm`、`$spd` 运动指令本身不返回 OK，不能用缺少 OK 判定运动命令发送失败。

## 4. 配置与核对初始化参数

### 4.1 参数、目标值与对应函数

| 参数       | 当前目标或处理方式           | 串口命令               | 主控封装函数                                      | 作用                                 |
| ---------- | ---------------------------- | ---------------------- | ------------------------------------------------- | ------------------------------------ |
| 电机类型   | 当前 A→H1A、B→H1B 接法采用 2 | `$mtype:2#`            | `Motor_SetType(MOTOR_TYPE_310)`                   | 按厂家约定匹配控制及编码器方向       |
| 编码器线数 | **500**                      | `$mline:500#`          | `Motor_SetEncoderLines(500)`                      | 将计数与内部电机轴的转动对应起来     |
| 减速比     | **30**                       | `$mphase:30#`          | `Motor_SetReductionRatio(30)`                     | 将内部轴与减速箱输出轴的转动对应起来 |
| 死区补偿   | **本次先用 0**               | `$deadzone:0#`         | `Motor_SetDeadZone(0)`                            | 暂时关闭小输出补偿，后续按实测标定   |
| 车轮直径   | 实测直径，单位 mm            | `$wdiameter:实际直径#` | `Motor_SetWheelDiameter(实际直径)`                | 将输出轴转速换算为轮缘线速度         |
| PID        | 先保留 P=0.8、I=0.06、D=0.5  | 当前无需重新发送       | `Motor_SetPID(0.8f, 0.06f, 0.5f)`，仅需修改时调用 | 根据速度误差调整 PWM                 |

表格中的“实际直径”是填写说明，发送命令或编写代码时须替换成测量数值。界面中的“310”是本驱动板的类型名称；这里采用编号 2 的依据是手册规定的接线约定。

### 4.2 编码器线数：固定填 500

`mline` 填内部编码器轴每圈、单相的完整方波周期数。本电机填 **500**，不乘四倍频系数，也不乘减速比。

```text
$mline:500#
```

四倍频后的 2000、减速箱输出轴理论每圈的 60000，都不能直接作为这里的线数参数。配置后查询应显示 `Pulse_Line:500`。

### 4.3 减速比：1:30 填 30

减速比 1:30 表示内部电机轴约转 30 圈，输出轴转一圈。

```text
$mphase:30#
```

协议名称虽然是 `mphase`，本手册中该参数的含义是减速比。本次原始回包已经为 `Pulse_Phase:30`，无需为排查抖动而更改它。

### 4.4 死区补偿：当前采用 0

输出较小时，电机可能因摩擦等原因无法启动；死区补偿用于对较小的控制输出进行补偿。手册说明 PWM 控制会叠加该补偿，默认值为 1600，允许范围为 0—3600。

本次采用：

```text
$deadzone:0#
```

当前先保留该设置，后续根据实际起步、低速和负载表现标定。它是驱动板的输出补偿参数，不是 CubeMX 中互补 PWM 的死区时间。

### 4.5 轮径：填写实际车轮直径

单位为 **mm**。之前回包中的 `67.000` 仅代表已保存的设置，不能证明实物轮径为 67 mm。

只有实际轮径为 67 mm 时，才采用以下命令或对应函数：

```text
$wdiameter:67#
```

```c
Motor_SetWheelDiameter(67.0f);
```

轮径用于 `spd` 的线速度换算。填写完整车轮直径；尚未装轮子或未测量时，可先做第二部分的原始反馈和开环测试，确认轮径后再验证以 mm/s 为单位的闭环速度。

### 4.6 PID：当前保留，正常初始化不恢复出厂

本次原始 PID 为：

```text
P:0.800  I:0.060  D:0.500
```

线数和死区调整后用户已反馈可以运行，先保留这些 PID 值，不为“初始化”而反复发送 PID 命令。按手册，修改 PID 会使驱动板重启；后续需要调参时，在电机停止状态下进行，并等待板卡重新启动。

**正常上电不要调用 `Motor_ResetFlash()` 或发送 `$flash_reset#`。** 该命令会恢复出厂参数并重启，之后必须重新核对、配置 MG513 GMR 的线数等参数。

### 4.7 首次配置的发送顺序与读回标准

首次使用新板、更换电机或恢复出厂后，先停止输出，再逐条配置；每条等待成功回复后继续：

```text
$mtype:2#
$mline:500#
$mphase:30#
$deadzone:0#
```

再单独设置实测轮径，最后查询：

```text
$read_flash#
```

对于本次已读回类型 2、减速比 30 的驱动板，修正抖动时实际需要调整的是线数和死区，其余已匹配的参数不必重复写入。

核对以下目标值。此表是**配置后的验收目标**，不是尚未提供的实测回包：

| 回包字段         | 应核对的值                                |
| ---------------- | ----------------------------------------- |
| `Motor_type`     | 2，前提是采用本流程的 A 对 A、B 对 B 接法 |
| `Pulse_Line`     | **500**                                   |
| `Pulse_Phase`    | **30**                                    |
| `Dead_Zone`      | **本次配置为 0**                          |
| `wheel_diameter` | 与实际车轮直径一致                        |
| `P`、`I`、`D`    | 当前保留 0.800、0.060、0.500              |

若线数 500 无法正确读回，先核对指令解析及固件支持情况，不继续闭环速度测试。

### 4.8 首次参数配置与每次上电的区别

类型、线数、减速比、死区、轮径和 PID 都会保存到驱动板 Flash。配置并读回正确后，正常断电重启不需要重复写入；更换硬件、恢复出厂或确需重新标定时再改。

主控每次上电主要完成以下运行准备：

| 步骤           | 当前工程对应操作                                             | 说明                                                   |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| 初始化主控串口 | `MX_USART1_UART_Init()`                                      | 当前使用 USART1，PA9/PA10，115200 8N1                  |
| 将输出置零     | `Motor_SetPWM(0, 0, 0, 0)`                                   | 在串口和驱动板通信就绪后发送                           |
| 按需要设置上报 | 关闭为 `Motor_SetUpload(0, 0, 0)`；只上报速度为 `Motor_SetUpload(0, 0, 1)` | 上报开关不掉电保存；与电机启停独立                     |
| 核对配置       | `Motor_ReadFlash()`                                          | 通过接收回包确认实际参数，尤其是首次接入或参数变更后   |
| 进入控制流程   | 按任务需要调用速度或 PWM 函数                                | 初始化阶段保持输出为零，非零运动指令由后续程序流程发出 |

当前 `motor.c` / `motor.h` 只负责组帧、参数检查与发送；函数返回 `HAL_OK` 表示主控串口发送完成，不代表驱动板已执行或确认。查询结果和 OK 回包仍需由电脑串口助手查看，或由主控接收代码处理。

当前 `bsp_loop()` 只发送速度命令，不会自动设置编码器线数等硬件参数；之前通过电脑配置并保存后，主控发送的速度命令会沿用这些参数。

**初始化完成标准：**接线、供电和通信已核对；编码器线数 500、减速比 30、当前类型与死区均读回正确；闭环速度测试前确认实际轮径。随后进入第二部分，按原流程核验反馈、开环与闭环表现。

# 第二部分：电机控制

## 5. 检查编码器反馈

先上报 10 ms 窗口内的计数：

```text
$upload:0,1,0#
```

预期收到 `$MTEP:…#`，四个值依次对应 M1、M2、M3、M4。当前重点观察**第一个数**：

- 静止时应接近 0。
- 轻转输出轴时应有变化；减速箱难以反拖时不硬拧，改在下一步低 PWM 转动中检查。
- 正反向转动时，计数正负方向应相反。

例如，下面只是格式示例，不是当前实测值：

```text
$MTEP:300,0,0,0#
```

它表示 Motor1 在对应 10 ms 窗口内计数为 300，不是 300 rpm。10 ms 是计数统计窗口，不保证串口包严格每 10 ms 到达。

如果需要核对每圈计数，切换为累计上报：

```text
$upload:1,0,0#
```

接收格式为 `$MAll:…#`。记录输出轴沿同一方向转一圈的起止值，按四倍频及标称减速比计算，绝对差应接近：

```text
500 × 4 × 30 = 60000 计数 / 输出轴圈
```

也可累计多圈后取平均。不要通过 `$read_flash#` 或恢复出厂来清零累计值，直接计算起止差即可。

驱动板资料主要展示霍尔编码器，未明确承诺 500 线 GMR 的最高输入频率。60000 是应核验的理论值，不表示该板已经实测确认采用此口径。计数口径或稳定性异常时先排查，不把它直接带入速度环。

## 6. 开环测试：正转、停止、反转

本步前提：通信正常，类型、线数、减速比和死区已经读回确认。反馈上报可切回：

```text
$upload:0,1,0#
```

### 6.1 小正向输出

```text
$pwm:200,0,0,0#
```

只有 Motor1 接收非零输出。短时观察是否启动和第一个编码器数值的方向，然后归零：

```text
$pwm:0,0,0,0#
```

如果 200 不足以启动，先归零，再逐级试 400、600。每次短时观察后归零，不持续让电机通电却不转；仍不转时先检查动力电源、动力线和驱动输出，不直接跳到最大值。

### 6.2 停稳后测试反向

若 200 已能正常启动，停稳后可试：

```text
$pwm:-200,0,0,0#
```

如果实际稳定启动值更大，改用已验证的较小启动值的负值。短时观察后再次停止：

```text
$pwm:0,0,0,0#
```

### 6.3 方向与停机验收

| 项目     | 应观察到的现象                                       |
| -------- | ---------------------------------------------------- |
| 正向 PWM | 电机向一个方向转动，编码器反馈方向与板卡闭环约定一致 |
| 负向 PWM | 转动方向相反，编码器反馈方向也相反                   |
| PWM 全零 | 动力输出归零，电机停止或自然减速停止                 |

正向 PWM 对应负反馈、反馈恒为 0 或方向不随反转变化时，先归零，检查编码器相位接法、类型配置以及反馈是否与 Motor1 配对，不继续闭环。排查时不交换编码器 VCC/GND。

**本步完成标准：**能够可控地正转、停机、反转，编码器反馈随转动合理变化。

## 7. 低速闭环测试

本步前提：实际轮径已确认，原始计数和反馈方向均已核对。轮径未确认或尚未装轮子时，先完成前面的开环与编码器检查，暂不照抄轮径示例。

### 7.1 设置实际轮径

轮径单位为毫米。**只有实际轮径为 70 mm 时**，才发送以下示例；其他轮径应替换为实际数值：

```text
$wdiameter:70#
```

用 `$read_flash#` 检查轮径读回是否正确。

### 7.2 打开速度上报并给低速目标

逐条发送：

```text
$upload:0,0,1#
$spd:50,0,0,0#
```

含义：Motor1 目标轮缘速度为 **+50 mm/s**，其他通道目标为 0。反馈格式为 `$MSPD:…#`，第一个值为 Motor1 的速度。

50 mm/s 不是 50 rpm。轮径为 70 mm 时，按下式计算约为 13.6 rpm：

```text
输出轴 rpm = 轮缘速度(mm/s) × 60 / [π × 轮径(mm)]
```

先观察能否平稳启动和接近目标，再停车。低速稳定后才逐步提高目标，例如试 100 mm/s；不同时改动多个参数。

### 7.3 停车及反向

调试时先发送：

```text
$pwm:0,0,0,0#
```

停稳后，可用低速负目标测试反向：

```text
$spd:-50,0,0,0#
```

测试后再次发送 PWM 全零。

如果突然加速、明显振荡、持续不启动或方向不符合预期，先停止并核对原始计数、线数、减速比、轮径与反馈方向。默认 PID 不代表已针对 500 线 GMR 调好，不靠盲目增大 PID 或死区来处理异常。

### 7.4 两种零指令的区别

| 指令            | 含义                                                 |
| --------------- | ---------------------------------------------------- |
| `$spd:0,0,0,0#` | 目标速度为零，PID 继续工作，受到扰动时可能输出纠正力 |
| `$pwm:0,0,0,0#` | PWM 输出归零；不保证特定芯片电气上的完全滑行状态     |

零速 PID 不等于绝对位置保持，也不能替代硬件停止手段。资料没有明确说明通信失联自动停机时限，不能依赖拔掉 USB 自动停车。

**本步完成标准：**低速正反向可控，反馈接近目标，停机有效，无明显振荡、异常电流或温升。

## 8. 结束测试与接入 STM32

结束本轮测试时，逐条发送：

```text
$pwm:0,0,0,0#
$upload:0,0,0#
```

确认停止，保存串口日志，关闭串口并切断动力电源。更改接线时保持断电。

电脑验证通过后，F103RCT6 通过 USART2 发送相同 ASCII 命令：

| F103RCT6        | 驱动板 |
| --------------- | ------ |
| PA2 / USART2_TX | RX2    |
| PA3 / USART2_RX | TX2    |
| GND             | GND    |

两端串口保持 115200 8N1。核心板按其规定供电，已独立供电时不直接并联另一 5 V 电源。控制端切换为 F103 后，避免电脑和主控同时向板卡发送指令。

采用板载速度闭环时，编码器接驱动板，由板卡完成测速和 PID；F103 负责目标速度、反馈接收、任务控制及停机逻辑。首次程序上电先输出全零，再进入明确的测试状态。厂家完整演示会自动切换多种运动状态，应先改为本流程的单路低速测试。

电脑串口助手用于开发台架测试；正式比赛应由车载程序按规则自主控制。

## 9. 常见异常排查

| 现象                  | 优先检查                                                     |
| --------------------- | ------------------------------------------------------------ |
| 设备管理器没有 COM 口 | Type-C 是否为数据线、USB 连接、串口驱动                      |
| COM 口打不开          | 是否选错端口，是否被另一个串口程序占用                       |
| `$read_flash#` 无回复 | COM 号、串口参数、ASCII 发送、完整的 `$…#`、供电             |
| 配置有回复，PWM 不转  | 12 V 动力电源是否接入，M1+/M1- 是否正确，当前 PWM 是否足够启动 |
| 电机转，反馈一直为 0  | 编码器 VCC/GND、H1A/H1B、线束接触、动力与反馈是否同属 Motor1 |
| 反馈方向错误          | 实际 A/B 接法、类型配置、动力极性与编码器方向的对应关系      |
| 线数 500 无法读回     | 实物固件是否支持该参数范围，实际指令是否被正确解析           |
| 闭环速度比例明显异常  | 500 线、30 倍减速、实际轮径、倍频计数口径和速度单位          |
| 低速抖动或突然加速    | 先停机，检查反馈方向、计数质量、死区和 PID，不直接提高增益   |
| 高速丢计数            | 信号质量、接线、电源、固件输入频率与采码能力；降速后对照核验 |
