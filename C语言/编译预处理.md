# 从**源代码**到可执行文件的步骤
```
预处理->编译->汇编->链接
```
## 预处理
预处理阶段不检查语法
1. 预处理主要任务：
	1. 头文件展开
	2. 宏替换
	3. 条件编译
	4. 删除注释
	编译时可以用`gcc -E`只进行到预处理
2. 头文件展开：`#include<>` VS `#include""`
	1. `<>`:包含系统定义的头文件(`/usr/include`)，搜索路径：`/usr/include`（系统的头文件目录）
	2. `""`:包含自定义的头文件，搜索路径：先在当前目录查找，再到系统的头文件目录查找；
	3. 编译时使用指令`gcc -I` 指定头文件第三方搜索路径，例如头文件不在当前目录中，而是在当前目录中的子目录`include`中，那么可以使用命令`gcc -I./include`这个命令
3. 宏替换
	1. 宏替换语法：`#define NAME Value`
	2. 替换逻辑：“傻瓜式“替换，注意事项：使用（）解决运算符优先级的问题
## 编译
将预处理文件编译成汇编文件，这时候会做语法检查
使用命令
```bash
gcc -S
```
可以只进行编译，生成一个`.s`文件，`.s`文件就是汇编文件
## 汇编
将汇编文件编译成目标文件（`.o`文件）
使用这个命令可以只进行到汇编阶段
```bash
gcc -c
```
会生成一个`.o`文件
## 链接
从目标文件生成可执行文件
“链接”就是把多个目标文件和库组合起来，解决函数、变量之间的引用关系。
1. **符号解析**：将函数调用与定义绑定（如 printf 绑定到 libc。编译器生成目标文件时，知道代码调用了 `printf`，但 `printf` 的具体实现位于 C 标准库中。链接器需要决定：**把 `printf` 的机器代码直接复制进程序，还是让程序运行时再去加载它。**） 
2. **重定位**：修正代码中的地址引用 
3. 静态链接 vs 动态链接
`.dll`就是动态库扩展名
# 宏定义
- 宏定义的作用
1. 提高代码的可读性和可移植性
2. 定义常量（可以用来杜绝幻数）
3. 定义函数（称为宏函数，用编译时间换内存空间）（`inline`关键字修饰函数，建议编译器在调用点展开，用空间换运行时间（消除函数调用开销），`inline` 函数应当避免包含可修改的 `static` 局部变量。不是任何函数加`inline`都会内嵌，函数最好不要太大，如果函数太大编译器就不会把这个函数内嵌。

## 宏替换的傻瓜式替换
为什么叫傻瓜式替换？可以看下面的例子
```c
#include<stdio.h>
#define SUM(a,b) a+b-a*b //宏函数
#define NEWSUM(a,b) (a)+(b)-(a)*(b)

int main()
{
	int result = SUM(1,2);
	printf("%d\n",result);//这个是正常的，得到结果1
	
	//注意，这个结果反直觉
	result = SUM(5+6,6*5);
	//它不会把5+6=1,6*5=30算出来代入，而是直接进行“傻瓜式”替换
	//5+6+6*5-5+6*6*5 = 216
	printf("%d\n",result);//所以这个结果是216
	//而不是：11+30-11*30 = -289
	
	//但是可以使用括号进行修正，例如上面的NEWSUM这个宏定义
	result = NEWSUM(5+6,6*5);
	//这时候再进行傻瓜式替换，得到(5+6)+(6*5)-(5+6)*(6*5)，得到结果-289
	
}
```

## 定义常量杜绝幻数
```c
#include<stdio.h>

int log(char* username,char* password)
{
	if(strcmp(username,"admin")==0&&strcmp(password,"admin")==0)
	{
		return 0;
	}
	return 1;
}

int main(){}
```
这时候就有问题了，有时候在实际编程的时候我们经常会突然脑子卡壳忘了0和1哪个是登陆成功，哪个是登录失败呢？这个情景是程序员经常遇到的情景，尤其是在项目庞大的时候，需要在许多代码里去翻找代码来确定0和1对应的意义。这个0和1在这里就叫幻数，为了避免幻数，宏定义的作用就体现出来了
我们可以这样做：
```c
#include<stdio.h>
#define LOG_SUCCESS 0
#define LOG_FAILED 1

int log(char* username,char* password)
{
	if(strcmp(username,"admin")==0&&strcmp(password,"admin")==0)
	{
		return LOG_SUCCESS;
	}
	return LOG_FAILED;
}
```
这样幻数的问题就得到了解决，代码的可读性大大提升
## 宏函数
```c
#include<stdio.h>
#define MAX(a,b) ((a)>(b))?(a):(b) //宏函数看上去像函数但是并没有按照函数的机制去处理

int max(int a,int b)
{
	return a>b?a:b;
}

int main()
{
	int a = 5;
	int b = 6;
	
	//开销大：给形参分配空间；要做一系列操作：函数调用、函数返回、分配空间、释放空间
	int max_num1 = max(a,b);
	
	//但是我们可以使用宏函数
	//只做傻瓜式替换，不再占用空间（在预处理阶段就替换完成了，占用编译时间，不占用运行时间）；不再进行函数调用那些繁琐的操作
	//频繁调用且短小的函数，最好优化成宏函数
	//缺点：不安全，因为傻瓜式替换，稍写不慎就会出错
	int max_num2 = MAX(a,b);
}
```
但是当宏函数复杂的时候又会遇到别的问题
```c
#include<stdio.h>
#define DOSOMETHING()\
	func1();\
	func2();
```
这个宏的本意是当调用函数`DOSOMETHING`时调用函数`func1`与函数`func2`
但是当我们这样进行的时候
```c
//x为bool类型的变量
if(x)
	DOSOMETHING();
```
这时候`DOSOMETHING`就会“傻瓜式展开”为下面的形式：
```c
//x为bool类型的变量
if(x)
	func1();
func2();
```
这就出现问题了！无论`x`是否为`true`都会执行函数`func2()`
如果我们使用`{}`括起来呢

```c
#include<stdio.h>
#define DOSOMETHING(){\
	func1();\
	func2();}
	
int main()
{
	if(a>0)
		DOSOMETHING();
	else{}
	return 0;
}
```
宏展开后，代码如下
```c
#include<stdio.h>
#define DOSOMETHING(){\
	func1();\
	func2();}
	
int main()
{
	int a = 1;
	if(a>0)
	{
		func1();
		func2();
	};
	else{}
	return 0;
}
```
由于在调用`DOSOMETHING`函数的时候后面有一个分号，宏展开之后就会在`if`的`{}`后面多一个分号，展开之后这个分号会残留在`{}`的尾部，这就会导致后面的`else`变成了游离的`else`，进而编译错误。但是如果调用`DOSOMETHING`时不加分号，也会导致编译报错。这也是一个问题。那有什么解决办法呢？
我们可以使用`do{...}while(0)`
```c
#include<stdio.h>
#define DOSOMETHING()do{\
	func1();\
	func2();\
	}while(0)
```
这时候展开之后的就是
```c
#include<stdio.h>
#define DOSOMETHING()do{\
	func1();\
	func2();\
	}while(0)
	
int main()
{
	int a = 1;
	if(a>0)
	{
		do{
			func1();
			func2();
		}while(0);
	}
	else{}
	return 0;
}
```
等价于
```c
#include<stdio.h>
#define DOSOMETHING()do{\
	func1();\
	func2();\
	}while(0)
	
int main()
{
	int a = 1;
	if(a>0)
	{
		func1();
		func2();
	}
	else{}
	return 0;
}
```
这时候就真的达到了我们想要的目的了
### 自定义函数VS宏函数
宏函数：
- 缺点：傻瓜式替换，不安全，实现复杂函数比较繁琐
- 优点：省去了函数分配内存、释放内存、调用、返回等一系列步骤，省去传参空间分配和释放，省去了函数调用和返回过程，提升了效率
自定义函数：
- 缺点：效率不高，因为需要发生函数的调用返回，空间的分配和释放一系列操作
- 优点：实现复杂函数相对于宏函数较为简单，安全
短小而频繁调用的函数可以利用宏函数定义
# 关于`#`与`##`
## `#`-字符串化
在C语言的宏中，`#`的功能是将其后面的宏参数进行字符串化操作（Stringfication），简单的说，如果你写`#param`，预处理器会把它直接“傻瓜式”替换成`"param"`（参数的内容用双引号包起来）
可以看看这个例子就显而易见了：
```c
#define STR(x) #x

int main()
{
	printf("%s\n",STR(hello));
	//展开后变成：printf("%s\n","hello");
	//输出：hello
}
```
哪怕参数里有表达式或空格，也会被当成一个整体字符串化：
```c
#define STR(x) #x

printf("%s\n", STR(1 + 2));
// 展开后变成：printf("%s\n", "1 + 2");
// 输出：1 + 2   （注意不是 3，因为它变成了字符串，不会进行计算）
```
这也就是为什么我要用“傻瓜式替换”来进行形容
再说下面的之前我先提一个知识点：
```c
printf("hellohello");
printf("hello" "hello");
printf("hello"   "hello");
```
这三个表达式完全等价，我相信聪明的你们一下子就能懂我意思了
所以有如下的使用技巧：
```c
#define PRINT_VAR(x) printf(#x " = %d\n", x)

int a = 10;
PRINT_VAR(a);   // 展开为 printf("a" " = %d\n", a);
                // 相邻字符串会自动连接，变成 "a = %d\n"
                // 输出：a = 10
```
## `##`-连接
简单的例子
```c
#define CONCAT(a,b) a##b

int xy = 10;
printf("%d\n",CONCAT(x,y));  //展开成xy，输出10
```
- `CONCAT(x, y)` → `x` 与 `y` 连接成 `xy`，然后作为变量名访问。
- 注意：拼接的不是字符串 `"xy"`，而是**标识符** `xy`。

# 内置宏
C语言编译器提供了很多内置宏，例如：
- `__LINE__`-得到当前所在的行数
- `__func__`-得到当前所在的函数名称
- `__DATE__`-得到当前日期
- `__TIME__`-得到当前时间
这两个宏可以用在 `printf` 中输出调试信息。
```c
printf("%s:%s   %s:%d",__DATE__,__TIME__,__func__,__LINE__);
```
内置宏大部分都是以`__`开头，所以我们自定义宏的时候一定要尽量避免`__`开头，防止和内置宏冲突
# `typedef`与`#define`的区别
`typedef`的主要作用是给数据类型重命名，能够提高移植性、可读性、编写效率
## `typedef`重命名函数指针
例子：
```c
#include<stdio.h>

//typedef int(*)(int,int) P_FUNC;错误，不可以这样写
//必须要这样写
typedef int (*P_FUNC)(int,int);

int add(int a,int b)
{
	return a+b;
}

int main(int argc,char *argv[])
{
	P_FUNC p_func = add;
}
```
对于初学者来说，这个写法就是这样规定的，没有为什么，初学者只需要记住即可。
## 下面进行`typedef`与`#define`的对比
- `#define`不能定义复杂的类型（如函数指针变量），但是`typedef`可以
- `#define`预处理阶段做傻瓜式替换，存在风险（预处理阶段不做语法检查），不安全
## 定义常量时，`#define`可以和`const`进行对比
- `#define` 定义的是**无类型的宏常量**，在预处理阶段进行文本替换，不分配内存，没有作用域和类型检查。
- `const` 变量是**带类型的只读变量**，分配内存，有正常的作用域和链接属性，可以是局部、全局，也可以是 `static`。它并不是单纯的“局部变量”。
# 条件编译指令
首先我们看一下常见的预处理指令
>预处理指令是以`#`开头的代码行。`#`号必须是该行除了任何空白字符外的第一个字符。`#`后是指令关键字，在关键字和`#`之间允许存在任意个数的空白字符。整行语句构成了一条预处理指令，该指令将在编译器进行编译之前对源代码块做某些转换。下面是部分预处理指令
- `#`：空指令，无任何效果
- `#include`：包含一个源代码文件
- `#define`：定义宏
- `#undef`：取消已定义的宏
- `#if`：如果给定条件为真，则编译下面的代码
- `#ifdef`：如果宏已经定义，则编译下面的代码
- `#ifndef`：如果宏没有定义，则编译下面的代码
- `#elif`：如果前面的`#if`给定条件不为真，当前条件为真，则编译下面的代码，其实就是`else if`的简写
- `#endif`：结束一个`#if......#else`条件编译块
- `#error`：停止编译并显示错误信息
对于条件编译，我们主要看`#if`,`#ifdef`,`#ifndef`,`#elif`,`#endif`这几个预处理指令
## 例1
```c
#include<stdio.h>

int main()
{
	#if 0
	printf("Hello,world");
	#endif
	printf("welcome");
	return 0;
}
```
在这个例子中，`#if`后面的0为假，故`#if`与`#endif`之间的`printf("Hello,world")`不会被编译器编译，故输出如下
```out
welcome
```
## 例2
```c
#include<stdio.h>

int main()
{
	#ifndef MAX_SIZE   //如果没有MAX_SIZE这个宏，那么编译器会编译下面的内容，直到遇到#else或者#endif
	printf("No MAX_SIZE");
	#else     //否则编译器编译下面的内容，直到遇到#endif
	printf("Have MAX_SIZE");
	#endif
}
```
# `gcc`指令添加宏定义
我们在使用指令编译时，可以使用`-D`让编译器添加宏定义，假设我们的cpp文件名为`demo.c`
```bash
gcc demo.c -DMAX_SIZE -o demo
```
这里`-DMAX_SIZE`的意思就是在预处理阶段定义如下的宏
```c
#define MAX_SIZE
```
同理，我们也可以进行复制，如下
```bash
gcc demo.c -DMAX_SIZE=1024 -o demo
```
即在预处理阶段定义如下的宏
```c
#define MAX_SIZE 1024
```
假如上面例2的程序是`demo.c`，如果我们执行：
```bash
gcc demo.c -o demo
./demo
```
那么就不会有`MAX_SIZE`这个宏被定义，输出为：
```out
No MAX_SIZE
```
如果我们执行：
```bash
gcc demo.c -DMAX_SIZE -o demo
./demo
```
那么就有`MAX_SIZE`这个宏被定义，输出为：
```out
Have MAX_SIZE
```
# 命名可变宏参数
在 C 语言中，**命名可变参数宏**（Named Variadic Macros）是 C99 标准引入的一项强大特性。它允许开发者定义带有可变数量参数（variadic arguments）的宏，并且可以将这些可变参数绑定到一个具体的名称（通常是 `__VA_ARGS__`），从而在宏的替换体中灵活地使用它们。
在定义宏时，使用省略号`...`表示可变参数。
例如
```c
#include <stdio.h>
#define LOG_INFO(fmt,...)printf("[INFO]" fmt "\n",__VA_ARGS__)

int main(int argc,char** argv)
{
    int year = 2025;
    int month = 10;
    int day = 12;
    LOG_INFO("[%d年%d月%d日]",year,month,day);
    return 0;
}
```
这个代码输出
```
[INFO][2025年10月12日]
```
## 宏定义解析
```c
#define LOG_INFO(fmt,...)printf("[INFO]" fmt "\n",__VA_ARGS__)
```
- `fmt`：固定参数（必须提供）
- `...`：表示可变参数部分（0个或多个）
- `__VA_ARGS__`：预处理器的特殊占位符（唯一标准写法）
	- 它不是变量名，而是C预处理器的内置关键字
	- 作用：原样插入调用时传入的可变参数部分
本质上，这个`...`与`__VA_ARGS__`还是傻瓜式替换
也就是，我们执行这个代码
```c
LOG_INFO("[%d年%d月%d日]",year,month,day);
```
预处理时，直接傻瓜式替换，把`fmt`替换为`"[%d年%d月%d日]"`，把`__VA_ARGS__`替换为`year,month,day`
```c
printf("[INFO]" "[%d年%d月%d日]" "\n",year,month,day);
```
然后，根据字符串拼接机制，这行代码等价于
```c
printf("[INFO][%d年%d月%d日]\n",year,month,day);
```
但是，这里有一个问题，如果后面的参数为空
```c
LOG_INFO("[%d年%d月%d日]");
```
那么就会傻瓜式替换为
```c
printf("[INFO][%d年%d月%d日]\n",);
```
我们会发现后面多了一个逗号！这就会出错
为了解决这个问题，我们给`##`符号加上特殊规定，如果`##`前面是逗号并且后面的`__VA_ARGS__`是空的，那么就会直接把前面的逗号吞掉，也就是说代码可以这样写
```c
#include <stdio.h>
#define LOG_INFO(fmt,...)printf("[INFO]" fmt "\n",##__VA_ARGS__)

int main(int argc,char** argv)
{
    int year = 2025;
    int month = 10;
    int day = 12;
    LOG_INFO("[%d年%d月%d日]",year,month,day);
    return 0;
}
```
这样就可以解决后面的可变参数数量为0的问题了。

>注意事项：
>**非标准特性**：这种“`, ##__VA_ARGS__` 吞逗号”的行为，实际上是 **GCC 和 Clang 编译器的扩展（GNU Extension）**，在严格的 C99/C11 标准中并未定义。
>但是，这已经成为了事实上的行业标准。几乎任何程序员都默认这是可以使用的

另外，GCC认为`__VA__ARGS__`太长了，就加了一个拓展语法：可以在`...`前面加上自定义标识符
```c
#include <stdio.h>
#define LOG_INFO(fmt,args...)printf("[INFO]" fmt "\n",##args)

int main(int argc,char** argv)
{
    int year = 2025;
    int month = 10;
    int day = 12;
    LOG_INFO("[%d年%d月%d日]",year,month,day);
    return 0;
}
```
这个代码与刚刚的代码完全等价。
## 在代码调试上的应用
对于这一块内容，我们需要先了解一个前置知识，可以看下面的代码块进行学习，正好利用我们刚刚说的命名可变宏参数 
```c
#define __DEBUG__
#ifdef __DEBUG__
#define debug_msg(fmt, args...) printf(fmt,##args)
#else
#define debug_mag(fmt, args...)
#endif

//这里如果宏__DEBUG__被定义了的话，那么debug_msg完全等价于printf

int main()
{
	debug_msg("%d\n",10);
	//输出10
	
	debug_msg("Hello,world\n");
	//输出Hello,world
	
	
}
```
很显然，这段代码块的宏定义主要的作用就是想要把`printf`关键字替换为`debug_msg`关键字。但是这有什么用呢？事实上在实际开发中，尤其是在错误排查、测试调试时，这段代码有很强大的作用，能大大提高调试效率。
为了介绍，我们引入一个段错误示例，看下面的代码
```c
#include<stdio.h>

int main()
{
	char *ptr = "welcome";
	//这里ptr指向的是字符串welcome的首字母，即指向字符w
	
	*ptr = 'w';
	//错误！未定义行为，大多数系统会段错误
	
	ptr++;
	//指针往后移一位，指向字符e，完全合法
	
	*ptr = 'w';
	//错误！未定义行为，大多数系统会段错误
	
	return 0;
}
```
为什么不能解引用指针然后修改呢？
### 原因分析
- `"welcome"` 是**字符串字面量**
- 通常存放在**只读存储区（如 `.rodata`）**
- `ptr` 只是指向它，并没有拷贝数据
下面这段代码
```c
*ptr = 'w';
```
相当于在做修改只读内存，会直接出现段错误`Segmentation fault`。
下面这两个定义字符串的方式是有区别的
```c
char str1[] = "hello";
char *str2 = "hi";
```
### 两者的区别
- 第一种方式会在可写内存中创建数组副本，因此可以修改其内容
- 第二种的指针指向只读区，

有了上面这个段错误例子的铺垫，下面我们来系统介绍一下这个`debug_msg`到底有什么用。
看下面这个例子
```c
#include<stdio.h>

int main()
{
	char* ptr = "welcome";
	
	ptr++;
	*ptr = 'L';
	printf("%s:%d\n",__func__,__LINE__);
	
	ptr++;
	*ptr = 'L';
	printf("%s:%d\n",__func__,__LINE__);
	return 0;
	
	//注意：指针移动（ptr++）本身是合法的，
	//问题出在对只读内存进行写操作。
}
```
这里我们通常会使用`printf("%s:%d",__func__,__LINE__);`进行错误排查
但是如果我们要把这个错误排查的代码给去掉，这两行都注释掉也许是可行的，但是当我们的项目足够庞大呢？大量的`printf`非常难管理，这就会是一个非常鸡肋的办法。解决方案就是利用`debug_msg`宏定义
```c
#include<stdio.h>
#define __DEBUG__
#ifdef __DEBUG__
#define debug_msg(fmt, args...) printf(fmt,##args)
#else
#define debug_msg(fmt, args...)
#endif

int main()
{
	char* ptr = "welcome";
	
	ptr++;
	*ptr = 'L';
	debug_msg("%s:%d\n",__func__,__LINE__);
	
	ptr++;
	*ptr = 'L';
	debug_msg("%s:%d\n",__func__,__LINE__);
	return 0;
}
```
利用预处理阶段，通过是否定义宏`__DEBUG__`，在编译期决定是否保留调试代码，从而实现零运行时开销的调试机制。这种方式相比运行时开关（如 if 判断），不会引入额外的运行时开销。
#### 注：什么是运行时开关？
```c
int debug = 1;

if (debug) {
    printf("value = %d\n", x);
}
```
这里的`debug`就是运行时开关。
**运行时开关多出来的开销：**
- 判断 `if (debug)`（CPU 要执行）
- 分支预测（可能影响性能）
- 代码体还是会被编译器编译
而条件编译（预处理阶段）可以直接移除某些代码，从而避免任何运行时开销。
>但是需要注意一点，实际工程中，宏通常使用全大写命名（如 `DEBUG`、`MAX_SIZE`），
并避免使用以下划线开头的宏（如 `__DEBUG__`），因为这类名称通常保留给编译器或标准库使用。这一点需要特别注意一下。
## 防止头文件重复包含
在介绍这个之前我们先简单介绍一下`extern`关键字
### `extern`关键字
#### 在`.h`中使用关键字`extern`
```c
//a.h
extern int a;
```
在 `.h` 头文件中，使用 `extern` 声明变量
可以让所有包含该头文件的 `.c` 文件访问该变量，
但变量的定义必须在某一个 `.c` 文件中完成。
注意，这里一定不要这样写
```c
//a.h
extern int a = 10;
```
这不是单纯声明，而是带初始化的`extern`，本质上是定义
假如有：
```c
//main.c
#include"a.h"
```

```c
//other.c
#include"a.h"
```
那么在预处理阶段，头文件展开后会变成
```c
extern int a = 10;//在main.c里
extern int a = 10;//在other.c里
```
这会在链接阶段导致“multiple definition”错误。
**所以，不要在头文件中对 `extern` 声明的变量进行初始化，否则会导致多个源文件中出现重复定义。**
#### 在`.c`中使用关键字`extern`
作用：在当前文件中“声明别人家的变量”

```c
//b.c
extern int g_val;
void func()
{
    printf("%d\n", g_val);
}
```
含义： 
> “我这个文件要用 g_val，但它定义在别的地方”
> 每个 .c 文件都会被独立编译，因此需要通过 extern 声明来告知编译器该变量在其他编译单元中定义。

#### 一句话核心
`.h` 里的 extern 是“对外声明接口”，`.c` 里的 extern 是“临时使用声明”

现在我们有了这些基础，看下面这个多文件程序
```c
//func1.h
int a = 5;
extern void func1();
```

```c
//func1.c
#include<stdio.h>
extern int a;

void func1()
{
	printf("a = %d\n",a);
}
```

```c
//func2.h
#include"func1.h"

int b = 6;

extern void func2();
```

```c
//func2.c
#include<stdio.h>
extern int b;

void func2()
{
	printf("b = %d\n",b);
}
```

```c
#include<stdio.h>
#include"func1.h"
#include"func2.h"

int main()
{
	func1();
	func2();
}
```
这个程序看似是正确的，实则暗藏玄机。在编译时，编译器会报错，显示`a`重复定义。这是为什么呢？我们把头文件展开看看
```c
#include<stdio.h>
int a = 5;
extern void func1();
#include"func1.h"

int b = 6;

extern void func2();

int main()
{
	func1();
	func2();
}
```
第一次展开之后我们发现由于`func2.h`中包含`func1.h`，`func2.h`展开后会出现`func1.h`，然后编译器在预处理阶段又会再次展开这个`func1.h`，这就是我们口中所说的头文件重复包含，得到：
```c
#include<stdio.h>
int a = 5;
extern void func1();
int a = 5;
extern void func1();

int b = 6;

extern void func2();

int main()
{
	func1();
	func2();
}
```
这就是问题所在！变量`a`出现了重复定义的情况。如何解决呢？下面给出解决方法。我们把那个多文件程序改成下面这个样子：
```c
#ifndef __FUNC1_H__
#define __FUNC1_H__
//func1.h
int a = 5;
extern void func1();
#endif
```

```c
//func1.c
#include<stdio.h>
extern int a;

void func1()
{
	printf("a = %d\n",a);
}
```

```c
#ifndef __FUNC2_H__
#define __FUNC2_H__
//func2.h
#include"func1.h"

int b = 6;

extern void func2();
#endif
```

```c
//func2.c
#include<stdio.h>
extern int b;

void func2()
{
	printf("b = %d\n",b);
}
```

```c
#include<stdio.h>
#include"func1.h"
#include"func2.h"

int main()
{
	func1();
	func2();
}
```
可以看到，我们只是给头文件加了下面的结构：
```c
#ifndef XXX
#define XXX

//......

#endif
```
仅仅三行代码就可以解决那个问题。
为什么呢，我们依然把`main.c`中的头文件进行展开
```c
#include<stdio.h>
#ifndef __FUNC1_H__
#define __FUNC1_H__
//func1.h
int a = 5;
extern void func1();
#endif

#ifndef __FUNC2_H__
#define __FUNC2_H__
//func2.h

#ifndef __FUNC1_H__
#define __FUNC1_H__
//func1.h
int a = 5;
extern void func1();
#endif

int b = 6;

extern void func2();
#endif

int main()
{
	func1();
	func2();
}
```
当第一个`func1.h`被`include`之后，这时候会定义宏`__FUNC1_H__`，然后当执行到`func2.h`中的`#include"func1.h"`时，由于实现判断是否定义了宏`__FUNC1_H__`，而原本已经包含了头文件`func.h`一次，那一次就已经定义了头文件`__FUNC1_H`，这样就完美避免了头文件重复包含的问题。
这就叫**头文件保护**(include guard)。
头文件保护现在还有一个新的方法
```c
#pragma once
//头文件内容
```
开始的时候输入一行`#pragma once`也可以实现头文件保护的功能
