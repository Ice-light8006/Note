# 原码、反码、与补码
- **原码**：最高位是符号位，`0` 表示正，`1` 表示负，其余位表示数值的绝对值。
- **反码**：
    - 正数的反码与原码相同；
    - 负数的反码是在原码基础上，符号位不变，其余位全部取反。
- **补码**：
    - 正数的补码与原码相同；
    - 负数的补码等于它的反码加 `1`。

>负数的补码转换回原码，可以这样做：
>**符号位不变，其余位取反，再加 1。**
# 通过C语言看一些例子
先介绍一下**截断机制**
截断机制是指：当把一个占内存较大的数据类型（比如 32 位的 `int`），赋值给一个占内存较小的数据类型（比如 8 位的 `char`）时，计算机无法将 32 个位全部塞进 8 个位里，于是只能采取“暴力砍掉高位，只保留低位”的操作。
## 例一
```c
#include <stdio.h>

int main(int argc,char** argv)
{
	printf("%d",~2);
	return 0;
}
```
这个代码的打印结果为
```
-3
```
现代计算机中的**有符号整数**通常使用补码表示。假设当前环境中的`int`为32位，其中最高位为符号位。则2的原码为
```
00000000 00000000 00000000 00000010
```
对应的补码为
```
00000000 00000000 00000000 00000010
```
然后`~2`，就是把2的补码的每一位都取反，得到
```
11111111 11111111 11111111 11111101
```
然后计算机会把这个视为某一个数字的补码。而补码符号位保持不变，其余位取反然后加一得到这个数字的原码。对这个数字符号位保持不变，其余数字取反然后加一，得到
```
10000000 00000000 00000000 00000011
```
这个数字就是-3的原码
所以打印结果为-3
## 例二
```c
#include <stdio.h>

int main(int argc,char** argv)
{
	signed char ch = 127;
	ch++;
	printf("%d\n",ch);
	return 0;
}
```
这里执行`ch++`时，`ch`首先发生整数提升，被提升为`int`，然后再自增，得到128
假设当前环境中的`int`为32位，则128的补码为
```
00000000 00000000 00000000 10000000
```
随后，结果128要转回`signed char`并存入`ch`。这会保留低8位
```
1000 0000
```
这会被视为某一个数字的补码。这个补码对应的数字为-128
所以打印结果为-128，而不是128。
## 例三
```c
#include <stdio.h>

int main(int argc, char **argv)
{
    signed char ch = -128;
    ch = ch - 1;
    printf("%d\n", ch);
    return 0;
}
```
假设 `signed char` 占 8 位，并且使用补码表示，则它的取值范围是：
```text
-128 ~ 127
```
`-128` 的 8 位补码为：
```text
1000 0000
```
执行：
```c
ch = ch - 1;
```
时，`ch` 会先进行整数提升，转换为 `int`，所以实际先计算：
```text
-128 - 1 = -129
```
`-129` 可以由 `int` 正常表示，因此这里的减法本身没有发生 `int` 溢出。
随后，需要把 `-129` 转换回 8 位的 `signed char`。由于 `-129` 超出了 8 位 `signed char` 的表示范围，在常见的补码实现中，会保留它的低 8 位。
从底层的 8 位补码运算角度，也可以这样观察：
```text
  1000 0000    -128
+ 1111 1111      -1
-------------
1 0111 1111
```
由于只保留 8 位，最左边产生的第 9 位进位被丢弃，剩下：
```text
0111 1111
```
`0111 1111` 按照 8 位补码解释就是：
```text
127
```
因此，在常见的 8 位补码实现中，程序通常打印：
```text
127
```
需要注意：将超出范围的整数转换为有符号整数类型，其结果是实现定义的。因此 C 标准并不保证所有平台都一定得到 `127`，只是现代常见平台通常如此。
## 例4
```c
#include<stdio.h>
#include<string.h>

int main(int argc,char** argv)
{
	char s[1024];
	for(int i = 0;i<1000;i++)
	{
		s[i] = -i-1;
	}
	int len = strlen(s);
	printf("%d\n",len);
	return 0;
}
```
这个代码的输出结果为
```
255

```
为什么呢？首先我们分析`s[i]`的值到底是什么
`char`的范围为-128~127
则当`i`取0到127时，不会发生越界，照常存入数组
```
s[0] = -1
s[1] = -2
s[2] = -3
...
s[126] = -127
s[127] = -128
```
当`i`取128时，`-i-1`的结果为`int`类型的-129，对应的补码为（假设当前环境中的`int`为32位）
```
1111 1111 1111 1111 1111 1111 0111 1111
```
然后再转换为`signed char`会取右边较低的8位`0111 1111`，这个补码对应的数字就是127
那么
```
s[128] = 127
```
同理，有
```
s[129] = 126
s[130] = 125
...
```
直到`i`取255时，`-i-1`的结果为`int`类型的-256，对应的原码为（假设当前环境中的`int`为32位）
```
10000000 00000000 00000001 00000000
```
除符号位之外每一位取反，得到反码
```
11111111 11111111 11111110 11111111
```
再加一，得到补码
```
11111111 11111111 11111111 00000000
```
然后赋值给`s[255]`，就会取较低的八位`00000000`，即0
那么就有
```
s[255] = 0
```
则`s[255] = '\0'`，那么，从`s[0]`开始，遍历后面每一个字符，第一次遇到字符串结束符`'\0'`为`i`为255的时候，则字符串长度为`i=0`到`i=254`这段长度
故字符串长度为255，打印结果为255
