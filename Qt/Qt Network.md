### Qt Network 模块概览

`Qt Network` 是 Qt 框架中专门用于网络编程的官方模块。它巧妙地屏蔽了底层不同操作系统（如 Linux 原生的 Socket API 和 Windows 的 Winsock）的复杂差异，提供了一套高度封装、跨平台的 C++ 接口，使开发者能够非常优雅地构建基于 TCP/IP 协议栈的各种网络应用程序。

### 核心网络类介绍

在这个模块中，有几个出场率极高的核心类，它们分别对应不同的网络传输需求：

- **`QTcpSocket`**：这是你实现“电脑与 ESP8266 通信”最核心的工具。它封装了 TCP 客户端，负责发起三次握手连接，并提供安全、可靠、不乱序的双向数据流读写功能。
    
- **`QTcpServer`**：用于搭建 TCP 服务端。如果你的架构反过来，让电脑作为中心服务器去监听并接收成百上千个考勤机（ESP8266）的主动接入，就会用到它来分配独立的套接字。
    
- **`QUdpSocket`**：封装了无连接的 UDP 协议。UDP 虽然不保证数据绝对送达，但传输速度极快且开销小，常用于局域网内的设备广播发现（比如让 Qt 软件一键搜索局域网内所有的考勤机）。
    
- **`QNetworkAccessManager`**：处理 HTTP 和 HTTPS 协议的“大管家”。未来如果你需要让 Qt 软件调用外部的 Web API、下载云端文件，都由它来调度处理。
    

### 底层基石：QIODevice 与异步机制

理解 Qt Network 的运作逻辑，关键在于掌握它的两大设计哲学：

- **统一的 I/O 接口**：`QTcpSocket` 和 `QUdpSocket` 的底层都继承自 `QIODevice` 这个基类。这意味着，你在 Qt 里通过网络发送和接收数据（调用 `write()` 和 `readAll()`），与你操作本地文件（`QFile`）或操作物理硬件串口（`QSerialPort`）的 API 和手感几乎是一模一样的，极大地降低了学习成本。
    
- **事件驱动与纯异步**：网络通信存在不可控的延迟，Qt Network 强制采用了异步非阻塞设计。你不需要写 `while(1)` 去死等数据（这会导致 UI 界面直接卡死）。一切交给 Qt 的事件循环，当底层网卡收到数据时，`QTcpSocket` 会自动发射 `readyRead()` 信号，你只需在关联的槽函数里把数据取出来即可。
